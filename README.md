# Дашборды компании v0.4.0

Показатели служб АЛМИ Партнер в одном месте: служба персонала, техническая поддержка, технологические партнёрства. Светофор «норма — внимание — критично» по настраиваемым порогам, динамика к прошлому периоду, цели, реестры, загрузка отчётов из Excel, PDF-отчёты и выгрузки, структура компании с руководителями и подчинением, сквозной отчёт — статус компании сверху вниз по показателям подразделений, — входящие данные и интеграции с системами компании («По Делу», «Пульс проекта», Jira, Confluence, Bitrix24, Exchange, 1С), доступ по профилям для уровней сотрудников — от первого лица до рядового сотрудника, вход по учётной записи домена и журнал всех изменений.

## Возможности

- **Обзор** — статус вашей области из сквозного отчёта и главное по каждой доступной службе на одной странице: ключевые показатели, светофор, незаполненные показатели, свежесть данных, последние загрузки.
- **Служба персонала** — дашборд (приём и увольнение, текучесть с целью, воронка найма, светофор по месяцам, подразделения), реестр приёмов и увольнений, ввод данных месяца, сводка по месяцам/кварталам/полугодиям/годам, цели и бенчмарки, пользовательские дашборды.
- **Техническая поддержка** — дашборд недельного отчёта (нагрузка, трудозатраты по клиентам, AlterOS, AlterOffice, Project Server, каналы), недельный отчёт с загрузкой xlsx/csv, сравнение периодов, аналитика заявок Naumen SD, сопоставление отчёта и Naumen.
- **Партнёрства** — реестр сертификаций совместимости со светофором каждой записи, аналитика, сводка по годам, хронология.
- **Структура компании** — дерево подразделений с руководителями: оргсхема, схема подчинения «Люди», дерево с сотрудниками, таблица с численностью; поиск, «Где я», боковые панели подразделения и сотрудника.
- **Сквозной отчёт** — статус компании сверху вниз: финансовые, операционные и вычисляемые из данных служб показатели подразделений, свёртка по структуре, светофор по порогам или отклонению от цели, «почему такой статус», матрица «подразделения × показатели», оргсхема статусов, тренды за 12 месяцев, нарушения полноты, отметки «под контролем», PDF; каждый видит отчёт в пределах своей области, глубины детализации и классов данных. Ввод показателей формой и загрузкой Excel, каталог показателей.
- **Входящие данные** — один путь для любых файлов с данными: папка «Входящие» на сервере, загрузка, приём по API с ключом `dash_…` (1С, скрипты), вложения задач «По Делу» и писем; распознавание набора (метрики и реестр службы персонала, недельный отчёт ТП, заявки Naumen, партнёрства, значения показателей, структура, сотрудники), план тем же движком, что ручная загрузка, применение сразу по правилу источника и набора или после подтверждения, повторы по SHA-256, срок хранения файлов.
- **Интеграции** — подключения к «По Делу» (структура, сотрудники, вложения задач), «Пульсу проекта» (показатели проектов), Jira (показатели по JQL), Confluence (публикация сквозного отчёта), Bitrix24 (сделки), почтовому ящику Exchange / Microsoft 365 / IMAP (вложения писем) и 1С (OData): проверка до сохранения, зашифрованные секреты с привязкой к адресу, разрешённые узлы, расписание, журнал запусков; ключи для входящих вызовов.
- **Доступ** — профиль доступа для уровня сотрудника («Высшее руководство», «Руководитель направления», «Руководитель подразделения», «Специалист», «Сотрудник») и личные настройки поверх него: уровни служб, область структуры, классы данных (персональные, финансовые), глубина детализации, исходные записи, выгрузка; «Мой доступ» в профиле; полномочия администрирования без роли администратора (структура, пользователи, сквозные отчёты, входящие данные, интеграции).
- **Вход по домену** — логин и пароль Active Directory / LDAP (LDAPS, StartTLS), сопоставление с учётными записями, профиль по группам каталога; синхронизация структуры и сотрудников с AD из интерфейса и по расписанию.
- **Администрирование** — пользователи и действующий доступ, профили доступа, подразделения, импорт и экспорт структуры и сотрудников (проверка → план → применение), показатели сквозного отчёта, интеграции и ключи для входящих вызовов, вход по домену, журнал изменений, палитры, состояние системы.
- **Интерфейс** — светлая и тёмная тема, фильтры в адресе страницы, личная настройка дашбордов, встроенные руководства и история версий.

## Быстрый запуск через Docker

```bash
git clone https://github.com/ayurasov/dashboards_serv.git && cd dashboards_serv
cp .env.example .env
openssl rand -hex 32        # вставьте в SECRET_KEY; задайте POSTGRES_PASSWORD и ADMIN_PASSWORD
docker compose up -d --build
curl -s http://127.0.0.1:8000/api/health
```

Запускаются три сервиса: `db` (PostgreSQL), `app` (приложение) и `worker` — планировщик: папка «Входящие» (том `inbox`, `/data/inbox`), запуски подключений по расписанию, очистка по сроку хранения. Откройте `http://127.0.0.1:8000` и войдите администратором (`ADMIN_USERNAME` / `ADMIN_PASSWORD`; если пароль не задан — временный пароль в `docker compose logs app`).

Демонстрационный стенд с данными, структурой компании, сквозным отчётом (14 показателей за 12 месяцев) и учётными записями разных уровней доступа: `DEMO_DATA=true docker compose up -d --build`.

| Логин | Пароль | Кто это |
| --- | --- | --- |
| `admin` | `admin123` | администратор |
| `ceo` | `ceo12345` | генеральный директор — профиль «Высшее руководство»: вся компания на один уровень |
| `tech_dir` | `td123456` | технический директор — «Руководитель направления»: своё направление, вводит операционные показатели |
| `engineer` | `en123456` | инженер техподдержки — «Сотрудник»: без служб, сквозной отчёт своей группы без денежных показателей |
| `hr_head`, `tp_lead`, `product`, `viewer`, `it_viewer` | `hr123456`, `tp123456`, `pp123456`, `view1234`, `it123456` | руководители и пользователи служб (подробно — руководство администратора, раздел «Демонстрационный стенд») |

Вход по учётной записи домена и синхронизация с Active Directory настраиваются переменными `AUTH_LDAP_*` и `AD_SYNC_*`; часовой пояс компании — `TIMEZONE`; входящие данные и интеграции — `INBOX_*`, `INBOUND_RATE_LIMIT`, `PUBLIC_URL`, `HTTPS_PROXY` и `<ВИД>_ALLOWED_HOSTS` (руководство по развёртыванию). `SECRET_KEY` шифрует секреты подключений — после его смены их нужно ввести заново. Команды обслуживания в контейнере: `docker compose exec -w /app/backend app python -m app.cli <команда>`.

## Разработка

```bash
# сервер (порт 8000)
cd backend
python3.12 -m venv .venv && . .venv/bin/activate
pip install -r requirements-dev.txt
DEMO_DATA=true python -m app.cli migrate        # SQLite ./dashboards.db, демо-данные
uvicorn app.main:app --reload
INBOX_DIR=./inbox python -m app.cli worker       # планировщик: папка «Входящие» и расписания (отдельный терминал)

# интерфейс (порт 5173, /api проксируется на 8000)
cd frontend
npm ci
npm run dev
```

Для работы с PostgreSQL задайте `DATABASE_URL=postgresql+psycopg://user:pass@localhost:5432/dashboards`.

## Тесты и проверки

```bash
cd backend && ruff check . && pytest                       # + TEST_POSTGRES_URL=… — миграции на PostgreSQL
cd frontend && npm run lint && npm test && npm run build
cd frontend && E2E_BASE_URL=http://127.0.0.1:8000 npx playwright test   # сервер с DEMO_DATA=true
locust -f loadtest/locustfile.py --host http://127.0.0.1:8000 --users 1000 --spawn-rate 25 --run-time 6m --headless
```

CI (GitHub Actions): `backend-ci` (ruff, pytest с PostgreSQL 16, миграции с нуля), `frontend-ci` (ESLint, Vitest, сборка), `e2e` (Playwright на демо-данных).

## База данных и миграции

Схемой управляет только Alembic; `python -m app.cli migrate` применяет миграции (под блокировкой на PostgreSQL), обновляет справочники и создаёт первичного администратора. В Docker это происходит при старте контейнера. Тест сверки схемы не даёт моделям и миграциям разойтись. Базы версий до 0.1.0 обновляются миграцией `0012_v0_1_0_schema` с переносом всех данных — см. [регламент](docs/runbooks/upgrade-to-0.1.0.md); 0.1.0 → 0.2.0 — миграцией `0014_org_access` (структура компании и доступ, откат поддерживается) — см. [регламент](docs/runbooks/upgrade-to-0.2.0.md); 0.2.0 → 0.3.0 — миграцией `0015_reports` (сквозные отчёты: только новые таблицы, откат поддерживается) — см. [регламент](docs/runbooks/upgrade-to-0.3.0.md); 0.3.0 → 0.4.0 — миграцией `0016_integrations` (входящие данные и интеграции: только новые таблицы, откат поддерживается) и новым сервисом `worker` — см. [регламент](docs/runbooks/upgrade-to-0.4.0.md).

```

  app/core        конфигурация, база, миграции, безопасность, ошибки, журнал

  app/schemas     схемы Pydantic
  app/services    аналитика служб, светофор, доступ, структура компании, сквозные отчёты, входящие данные и наборы, LDAP и AD, журнал, кэш, импорт/экспорт, PDF, справочники
  app/integrations каркас подключений (HTTP-клиент, запуск и расписание) и коннекторы систем компании
  app/worker.py   планировщик (python -m app.cli worker)
  app/api         роутеры FastAPI и зависимости прав
  app/data/demo   наборы данных демо-стенда
  migrations      Alembic (0012 — схема 0.1.0, 0014 — структура компании и доступ 0.2.0, 0015 — сквозные отчёты 0.3.0, 0016 — интеграции и входящие данные 0.4.0)
  scripts         перенос SQLite → PostgreSQL
  tests           pytest
frontend/
  src/components  оболочка, компоненты дизайн-системы, графики
  src/views       экраны служб, администрирования, справки
  src/domain      предметная логика экранов (с тестами)
  e2e             Playwright
docs/             руководства, история версий, release notes, ADR, регламенты, производительность
loadtest/         нагрузочный сценарий Locust
tools/docs/       сборка руководств в PDF и DOCX, снимки экрана
```

## Версии и ветки

Версия — `backend/app/__init__.py` и `frontend/package.json`; ветка разработки версии — `vX.Y.Z`. Каждая версия сопровождается записью в CHANGELOG, историей версий, release notes и обновлёнными руководствами и тестами.
