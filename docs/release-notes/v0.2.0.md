# Release notes — v0.2.0

Ветка `v0.2.0` от `v0.1.0`. Структура компании, модель доступа 2.0 (профили доступа и личные настройки), вход по учётной записи домена и синхронизация с Active Directory. Миграция `0014_org_access`; доступ существующих пользователей не меняется, откат поддерживается. Решения — ADR-0007 (структура), ADR-0008 (пользователи и LDAP), ADR-0009 (модель доступа); следующий шаг — сквозные отчёты, светофоры и статусы по уровням сотрудников (ADR-0010, версия 0.3.0).

## Для сотрудников

- **Структура компании** — новый раздел меню: оргсхема карточками, «Люди» (кто кому подчиняется), дерево с сотрудниками и таблица с численностью и выгрузкой; поиск по подразделениям и людям, «Уровней», «Где я», боковая панель подразделения и сотрудника; руководитель — по структуре или назначенный явно, с отметкой, откуда он взялся.
- **Мой доступ** — в профиле простыми словами: профиль доступа, службы, область, персональные и финансовые данные, глубина детализации, реестры, выгрузка. «Нет доступа» объясняет причину; недоступные разделы и кнопки скрыты.
- **Вход по домену** — логин и пароль домена, как в Windows (если включён в компании); понятные сообщения «Сервер домена не отвечает» и «Учётной записи в системе нет».
- **Незаполненные показатели** — показатель со светофором без значения теперь «Нет данных», а не «Критично»; пропуск отмечается красным как критичное нарушение полноты: на дашборде персонала (с кнопкой «Заполнить»), на «Обзоре», на вводе данных и в PDF.
- **Отчёты** — PDF по фильтрам страницы (диапазон сводки персонала, несколько лет недельного отчёта, фильтры партнёрств), время — местное.
- **Исправления по итогам функциональной проверки**: «Не удалось загрузить» с «Повторить» вместо пустых дашбордов, цели года по данным своего года, сравнение периодов ТП только равных интервалов, ось месяцев Naumen, окна и графики, раскладка на телефоне и планшете.
- Повторно входить после обновления не нужно; доступ прежний.

## Для администраторов

- **Пользователи**: сводка (всего · активных · отключено · без доступа · по домену · администраторов), фильтры по роли, статусу, подразделению, профилю и способу входа; создание с временным паролем, входом по домену или без доступа; «Выдать доступ»; «Перевести на пароль системы» для доменных учётных записей; удаление с предложением отключить; защита себя и последнего администратора.
- **Доступ**: профиль доступа + личные настройки по каждому измерению («как в профиле» / «задано лично»), уровни служб с «нет доступа» и своей областью службы, дополнительные подразделения, «Действующий доступ» с источником каждого значения и списком подразделений области.
- **Профили доступа**: пять встроенных профилей уровней сотрудников, свои профили, сравнение «кто что видит».
- **Полномочия** «Ведёт структуру компании» (`org.manage`) и «Ведёт пользователей и доступ» (`users.manage`) — без роли администратора.
- **Подразделения**: дерево с численностью и руководителями (★ основной), вложенные уровни, перенос, удаление без вложенных, типы уровней и предел вложенности.
- **Импорт и экспорт**: структура в JSON, сотрудники в Excel/CSV/JSON с разбором различий и вопросом «тот же человек?», быстрая загрузка списком, Active Directory — всегда проверка → план → применение.
- **Вход по домену**: состояние, замечания настройки, проверка подключения и поиска учётной записи; профили по группам каталога при создании учётной записи.
- **Журнал изменений**: подразделения, руководители, профили доступа, полномочия, загрузки структуры и сотрудников, синхронизация с AD, привязка к домену; границы дней — по местному времени.
- Демо-стенд: структура из 13 подразделений и девять учётных записей (`ceo`, `tech_dir`, `engineer` и прежние).

## API

- Новое: `/api/org/tree`, `/api/org/people/{id}` (+ `avatar`, `PATCH`), `/api/org/settings`, `/api/org/history`, `/api/org/export`, `/api/org/import/structure`, `/api/org/employees/export`, `/api/org/employees/import`, `/api/org/import/list`, `/api/org/sync/ad`; `/api/departments` — дерево, `PUT /api/departments/{id}/heads`; `/api/access/meta`, `/api/access/profiles`; `/api/users/{id}/access`, `/api/users/{id}/grant-access`; `/api/auth/config`; `/api/system/ldap`, `/api/system/ldap/test`.
- Изменено: `/api/users` — `{items, total, summary}` с фильтрами `role`, `status` (`no_access`), `department_id`, `profile_id`, `auth_source`; `POST /api/users` — `access_method` (`password` · `ldap` · `none`), `department_id`, `profile_id`, `capabilities`; `/api/auth/me` — `effective_access`, `capabilities`, способ входа, подразделение, профиль; `/api/auth/login` — ошибки `no_account` (403), `directory_unavailable` (503), `account_disabled` (403); `/api/hr/months/{key}` — `events_hidden`, `missing`; `/api/partnerships/analytics` — `record_lights`; `/api/tp/naumen/summary` без персональных данных — `responsibles_hidden`; `/api/overview` — `missing`.
- Права: реестры и карточки — исходные записи; ФИО и причины увольнения — персональные данные; все выгрузки — право на выгрузку. Ошибки — прежний формат `{detail, code, fields}`.

## Развёртывание

- Миграция `0014_org_access` выполняется при старте. **Перед обновлением сделайте резервную копию**; откат — восстановлением копии или `alembic downgrade 0013_data_revisions` образом 0.2.0. Регламент — `docs/runbooks/upgrade-to-0.2.0.md`.
- Новые переменные: `TIMEZONE` (по умолчанию `Europe/Moscow`), `AUTH_LDAP_*` (вход по домену), `AD_SYNC_*` (синхронизация с AD) — «Руководство по развёртыванию», разделы «Переменные окружения» и «Вход по домену и Active Directory». `docker-compose.yml` передаёт `TIMEZONE` и основные `AUTH_LDAP_*`; остальные — через `docker-compose.override.yml`.
- Синхронизация по расписанию: `docker compose exec -T -w /app/backend app python -m app.cli org-sync --ad --apply` (cron или systemd-таймер; коды выхода 0 — готово, 1 — ошибки в плане, 2 — каталог недоступен).
- Зависимости сервера: `ldap3`, `tzdata`.
- Нагрузочная проверка: 1000 одновременных пользователей всех уровней на 4 ядрах — p50 16 мс, p95 53 мс без ошибок сервера, оргсхема — p95 32 мс (`docs/performance/load-test-0.2.0.md`).
