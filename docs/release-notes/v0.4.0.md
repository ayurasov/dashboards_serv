# Release notes — v0.4.0

Ветка `v0.4.0` от `v0.3.0`. Интеграции и входящие данные: единый путь любых файлов в систему — из папки на сервере, загрузки, от 1С и других систем по API с ключом и от подключений — с распознаванием набора, планом и применением сразу или после подтверждения; подключения к «По Делу», «Пульсу проекта», Jira, Confluence, Bitrix24, почтовому ящику Exchange и 1С с проверкой, зашифрованными секретами, несколькими расписаниями и журналом запусков; «По Делу» (1.4.5+) и «Пульс» (0.6.0+) — по собственным ключам интеграций «Дашбордов»; отдельный процесс-планировщик. Миграция `0016_integrations` только добавляет таблицы; доступ пользователей не меняется, откат поддерживается. Решение — ADR-0011 (принято).

## Для сотрудников

- **«Входящие данные»** — новый пункт меню для тех, кто вводит данные служб, ведёт структуру или сквозные отчёты, и для полномочия «Входящие данные»: все файлы с данными — из папки на сервере, загрузки, по API и от подключений — с источником, набором, статусом и сводкой плана; счётчик ожидающих подтверждения в меню.
- **Распознавание набора** по подпапке, выбору, параметру API или содержимому: метрики месяцев и приёмы и увольнения службы персонала, недельный отчёт техподдержки, заявки Naumen, реестр партнёрств, значения показателей, структура компании, сотрудники.
- **План до применения** — тем же движком, что загрузка на странице службы: новые, изменённые и без изменений строки, «было → станет», ошибки по строкам, решения по сотрудникам; **Применить**, **Отклонить** с причиной, **Повторить** (заново или с другим набором), скачать исходный файл.
- **Статусы**: получен, распознан, ожидает, применён, отклонён, ошибка, повтор; тот же файл второй раз распознаётся как повтор и не применяется.
- **Загрузить файл** — Excel, CSV или JSON с выбором набора и «Применить сразу, если в плане нет ошибок»; ежемесячные метрики службы персонала теперь можно загрузить файлом.
- **Файлы из «По Делу» и почты**: вложение задачи списка с данными «По Делу» или письмо на выделенный ящик попадают во «Входящие» сами; задача отмечается комментарием системы «Дашборды» (с пометкой «интеграция») со статусом, у элемента видно, из какой задачи или письма файл.
- «Значения показателей» из файла: столбец «Очистить» = «да» удаляет сохранённое значение за месяц.
- **Контраст**: приглушённый текст и значки статусов — WCAG AA в светлой и тёмной теме; карточка файла во «Входящих» подстраивается под узкий экран («Файл» вместо «Скачать исходный файл», кнопки без переноса, таблица плана с прокруткой).

## Для администраторов

- **«Интеграции»** (`/admin/integrations`): подключения карточками — состояние, проверка, включение только после успешной проверки, действия «Запустить», журнал запусков со счётчиками по-русски; «Последняя ошибка» — только если она новее последнего успеха; форма настроек по описанию коннектора, выбор из 2–4 вариантов переключателями, поля JSON с проверкой при вводе.
- **Несколько расписаний** у подключения — до пяти записей, у каждой свои время (интервал или время по дням недели) и действия: например, «По Делу» одним подключением синхронизирует структуру раз в сутки и забирает файлы из задач каждые 30 минут. Запуск дольше двух часов — «Запуск прерван», подключение можно запустить снова.
- **«По Делу» и «Пульс проекта» по ключам интеграций**: «По Делу» 1.4.5 и новее выпускает «Дашбордам» ключ `podelu_…` (области «Структура компании», «Сотрудники», «Задачи и вложения», «Комментарии к задачам» и списки задач), «Пульс» 0.6.0 и новее — ключ `puls_…` (права «Проекты и планы», «Показатели проектов»); режим по умолчанию — ключ, служебная учётная запись остаётся для более ранних версий. Проверка показывает ключ, его области и чего не хватает каждому действию; понятные ошибки — ключ не принят, отозван, нет области, лимит частоты, нет API ключей.
- **Confluence — только администратор**: подключение публикует полный сквозной отчёт, поэтому его создаёт, настраивает и запускает администратор; сотрудник с полномочием «Интеграции» видит карточку только для чтения.
- **Коннекторы**: «По Делу» — структура и сотрудники (через план «Входящих», новые — без доступа, отключение отсутствующих), вложения задач списков с данными; «Пульс проекта» — проекты в работе, просроченные, в срок, прогресс и заблокированные задачи по подразделениям через «направление → подразделение», светофор проекта; Jira — показатели по JQL (число задач или сумма поля в часах) и признаки качества данных; «Проверить без записи» у Jira, Bitrix24 и 1С считает и значения показателей, которые будут созданы при запуске; Confluence — публикация сквозного отчёта страницей; Bitrix24 — выручка, выигранные сделки и воронка по ответственным; почтовый ящик — вложения писем разрешённых отправителей (EWS, Microsoft 365, IMAP); 1С — значения показателей по запросам OData; папка «Входящие» как подключение.
- **Секреты подключений** зашифрованы ключом от `SECRET_KEY`, привязаны к адресу (у «По Делу» и почтового ящика — ко всем адресам, куда уходят) и к подключению, в интерфейсе — только «задан»; при смене адреса или `SECRET_KEY` — «Секрет нужно ввести заново»; секреты вычищаются из текстов ошибок, журнала запусков и журнала сервера.
- **Правила «применять сразу»** — источник (папка, приём по API, подключение) × набор; план с ошибками всегда ждёт.
- **Папка «Входящие»**: состояние, «Проверить сейчас», последний разбор, планировщик («Работает», «Не отвечает», «Не запущен»), подпапки наборов, справка по передаче файлов; в корне набор распознаётся по содержимому, имя по шаблону — подсказка (+20 к оценке).
- **Ключи для входящих вызовов** `dash_…`: выпуск с областями «Приём файлов» и «Чтение статусов принятых файлов», показ один раз, выпуск заново, отзыв; ограничение частоты общее для всех процессов сервера (счётчик в базе); пример для curl и 1С.
- **Полномочия** «Входящие данные» (`data.manage`) и «Интеграции» (`integrations.manage`) — описания прямо говорят о доступе к данным. «Руководство администратора» и «?» на страницах администрирования — администратору и сотрудникам с любым полномочием администрирования.
- «Вход по домену» переехал на `/admin/directory`.
- Журнал изменений: элементы входящих, правила, подключения (создание, изменение, проверка, запуск, удаление), ключи.

## API

- Входящие: `GET /api/inbox` (фильтры, `counts` по статусам; у элемента — `note`, откуда файл), `POST /api/inbox` (загрузка), `GET /api/inbox/{id}`, `GET /api/inbox/{id}/file`, `POST /api/inbox/{id}/apply | reject | retry`, `GET /api/inbox/datasets`, `GET/PUT /api/inbox/rules` (`{rules: [{source, dataset, auto_apply}]}`), `GET /api/inbox/folder` (с шаблонами имён `folders[].patterns` и отметкой планировщика), `POST /api/inbox/folder/scan`; `/api/auth/me` → `inbox: {available, pending}` для пункта меню и счётчика.
- Интеграции: `GET /api/integrations/kinds` (поля, действия, `secret_url_fields` — поля привязки секретов, `order`, `admin_only`, `admin_only_note`, `counter_labels`), `GET/POST /api/integrations`, `POST /api/integrations/check` (несохранённые), `GET/PATCH/DELETE /api/integrations/{id}`, `POST /{id}/check`, `POST /{id}/run`, `GET /{id}/runs` (итог `interrupted` — «Запуск прерван»); `schedule` — список до 5 записей `{mode: interval | daily, minutes, time, weekdays, actions}` (прежний вид — один объект — принимается), в ответе у каждой записи `label` и `next_run_at`; у подключения `can_manage` и `current_error`; ключи — `GET/POST /api/integrations/keys` (`rate_limit` — предел частоты), `GET /api/integrations/keys/scopes` (подписи областей), `POST /keys/{id}/reissue`, `POST /keys/{id}/revoke`.
- `GET /api/inbox/folder` → `detect {threshold, name_bonus}` — как распознаётся файл в корне папки.
- Приём по API: `GET /api/inbound/v1/ping`, `POST /api/inbound/v1/files` (201 — принят, 200 — повтор), `GET /api/inbound/v1/files/{id}`; заголовок `Authorization: Bearer dash_…`, без сессии и CSRF; ошибки `{detail, code, error, message}` — `auth_required`, `invalid_key`, `scope_forbidden`, `payload_too_large`, `rate_limited` (с `Retry-After`).
- Значения показателей (`POST /api/reports/values/import` и набор `indicators`): столбец «Очистить», действие плана `clear`, в сводке `cleared`; загрузка без изменений не пишет журнал.
- Загрузки служб: `GET /api/hr/months/export.xlsx`, `POST /api/hr/months/import`, `POST /api/hr/events/import`, `POST /api/partnerships/import` (план → применение, 409 `import_has_errors`).
- Новые коды ошибок: `check_required`, `secret_rebind_required`, `run_in_progress`, `dataset_forbidden`, `wrong_status`, `content_purged`, `singleton`, `key_revoked`, `host_not_allowed`, `inbox_dir_not_set`, `admin_only`; у входящих — прежний `import_has_errors` (в свежем плане ошибки, ничего не записано).

## Развёртывание

- Миграция `0016_integrations` (таблицы `integrations`, `integration_runs`, `inbound_keys`, `inbox_items`, `inbox_rules`) выполняется при старте. **Перед обновлением сделайте резервную копию**; откат — восстановлением копии или `alembic downgrade 0015_reports` образом 0.4.0. Регламент — `docs/runbooks/upgrade-to-0.4.0.md`.
- **Планировщик** — сервис `worker` в `docker-compose.yml` (тот же образ, `python -m app.cli worker`): папка «Входящие», запуски по расписанию, прерванные запуски, очистка по сроку хранения, отметка о работе; несколько экземпляров безопасны. Без него — команды `inbox scan`, `inbox cleanup`, `integrations run` для cron (выключенное подключение — только с `--force`).
- **Том `inbox`** — папка «Входящие» (`/data/inbox`), общая для `app` и `worker`; можно заменить каталогом сервера, открытым по сети.
- Новые переменные (все необязательные): `INBOX_DIR`, `INBOX_SETTLE_SECONDS`, `INBOX_MAX_MB`, `INBOX_RETENTION_DAYS`, `INBOUND_RATE_LIMIT`, `WORKER_TICK_SECONDS`, `INTEGRATION_RUNS_KEEP`, `PUBLIC_URL`, `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `PODELU_ALLOWED_HOSTS`, `PULS_ALLOWED_HOSTS`, `JIRA_ALLOWED_HOSTS`, `CONFLUENCE_ALLOWED_HOSTS`, `BITRIX24_ALLOWED_HOSTS`, `EXCHANGE_ALLOWED_HOSTS`, `ONEC_ALLOWED_HOSTS` (`.company.ru` — домен и поддомены).
- **`SECRET_KEY` шифрует секреты подключений**: после его смены их нужно ввести заново — не меняйте ключ при обновлении и храните его вместе с резервными копиями.
- Новые зависимости: `requests`, `cryptography`, `exchangelib` (необязательная — только для режима EWS); тег образа по умолчанию — `0.4.0`.
- Сетевой доступ из `app` и `worker` к системам компании (HTTPS 443, IMAP 993); `HTTP_PROXY`, `HTTPS_PROXY` и `NO_PROXY` передаются в оба контейнера, `NO_PROXY` понимает узел, `.домен` и `*.домен`, `узел:порт`, `IP:порт`, сеть и `*`; IMAP — только напрямую. «По Делу» по ключу — с версии 1.4.5 (`/api/integrations/v1`), «Пульс проекта» — с 0.6.0 (`/api/integration/v1`); для более ранних — служебная учётная запись.
- **Нагрузочная проверка**: 1000 одновременных пользователей — p50 19 мс, p95 63 мс, p99 180 мс, без ошибок сервера; приём файла по API с планом и применением — 41 мс ([отчёт](../performance/load-test-0.4.0.md)).

## Документация

- Руководство пользователя: «Входящие данные» — откуда приходят файлы, наборы, как обрабатывается файл, статусы, список и карточка, применение, отклонение и повтор, повторы, ошибки, загрузка файла, ежемесячный файл службы, файлы из «По Делу» и почты.
- Руководство администратора: «Интеграции и входящие данные» — правила «применять сразу», папка, ключи, приём по API и из 1С, подключение и проверка, секреты, несколько расписаний, «Запуск прерван», журнал запусков, ошибки и разделы о каждой системе (права, настройки, действия, ошибки, примеры правил Jira, запросов 1С и сопоставления «Пульса»; ключи интеграций «По Делу» и «Пульса» — где и как их выпустить, области, проверка, типичные ошибки); полномочия «Входящие данные» и «Интеграции»; новый адрес «Входа по домену».
- Руководство по развёртыванию: планировщик, папка «Входящие» и права, переменные, сетевой доступ и прокси (`NO_PROXY`), версии «По Делу» и «Пульса» для ключей, `SECRET_KEY`, `exchangelib`, cron, обновление до 0.4.0. Регламенты [обновления до 0.4.0](../runbooks/upgrade-to-0.4.0.md) и [неполадок интеграций](../runbooks/integrations-troubleshooting.md), ADR-0011, CHANGELOG, история версий.
