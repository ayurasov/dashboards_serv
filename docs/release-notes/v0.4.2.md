# 0.4.2 — аудит интерфейса: понятность, доступность, устойчивость

Релиз по итогам полного аудита продукта (методика и находки — `docs/reviews/ui-audit-2026-11-20.md`):
интерфейсные улучшения, доступность, эксплуатационная честность и устойчивость тестов.
Схема базы, переменные окружения и настройки не меняются; обновление — обычный `docker compose up -d --build`.

## Понятность показателей

- Легенда семантики на «Обзоре» и дашбордах служб (`LightsLegend`): значок — статус по порогам светофора,
  стрелка — изменение к прошлому периоду. Тултипы у точки и стрелки в `KpiCard` («статус по порогам…»,
  «изменение к прошлому периоду… — динамика, а не статус»). Раньше «33 дня при цели 30 и зелёная стрелка ↓»
  читалось как противоречие (аудит A1).
- «Обзор»: карточки служб сортируются по критичности (red×2 + yellow + незаполненные), иконка службы
  тонирована худшим статусом её светофора, «Обновлено 14 дн. назад» — короткий формат без обрезки (A2–A4).
- «и ещё N» в статусах и причинах оформлено чипом (A5); подсказка «стрелки в ячейках» — только в виде
  «Матрица», где ячейки со стрелками есть (A8).
- График «Приём и увольнение»: подпись оси «чел.»; метка линии цели крупнее и цветом текста; нижний отступ
  сетки всех графиков +6px — подписи месяцев не прижаты к кромке карточки (A6, B5).

## Доступность

- Статусы различимы без цвета: норма — круг, внимание — треугольник, критично — ромб (`LightBadge`; WCAG 1.4.1).
- `--faint` (2.0–3.1:1) больше не используется для смыслового текста: 30 мест переведены на `--muted`
  (метки секций сайдбара, заголовки таблиц сравнения, «нет данных» в ячейках, единицы, счётчики «ноль»).
  `src/styles/contrast.test.js` дополнен проверкой: `color: var(--faint)` допустим только в списке
  декоративных мест, список не распухает от устаревших строк (B1).
- Мобильная шторка навигации: `aria-expanded`/`aria-controls` у бургера, фон под шторкой `inert`,
  закрытие по Escape (C1).
- Тач-экраны: чипы 40px, компактные кнопки 34px (`@media (hover: none) and (pointer: coarse)`; WCAG 2.5.5) (B3).
- Числа в ячейках матрицы выровнены вправо — столбец сравнивается по разрядам (B4).
- Логин: версия страницы — читаемым цветом, подвал ведёт к справке внутри приложения (A7).

## Надёжность и эксплуатация

- Коннектор «Папка „Входящие“» на `OSError` (чужой uid при bind-mount, пропавший носитель) отвечает
  «Нет доступа к папке … (причина). Проверьте…» вместо «Внутренняя ошибка коннектора — подробности в журнале
  сервера» (F1); тест — `test_folder_connector_reports_access_denied`.
- Планировщик пишет файл-сердцебиение (`WORKER_HEARTBEAT_FILE`, по умолчанию `/tmp/worker-heartbeat`,
  обновляется каждым тактом); `docker-compose.yml` проверяет его возраст healthcheck'ом — состояние `worker`
  видно в `docker ps`, а не только по журналу и экрану «Входящие → Папка» (F3).
- e2e: из `inbox.spec.js` убран serial-режим — падение одного теста больше не пропускает пять следующих;
  подняты таймауты settle-чувствительных проверок («Ожидает» в карточке входящих, переход «Обзор → отчёт») (D1–D2);
  добавлен проект `mobile-chromium` (Pixel 7, 390×844): `e2e/mobile.spec.js` держит инвариант «нет
  горизонтальной прокрутки» на 8 ключевых маршрутах и проверяет шторку с aria-атрибутами (D3).
- `docs/openapi.yaml` — версионируемый снапшот контракта (133 пути); `tests/test_openapi_snapshot.py`
  падает при расхождении с приложением (E3).

## Технические детали

- Канонические точки адаптива зафиксированы в `tokens.css` (640/960/1280): новые `@media` — только по ним,
  нестандартные значения из старых файлов сводятся к ближайшей при касании файла (B2, инкрементально).
- Тесты: `contrast.test.js` 37 проверок (было 35), новый снапшот OpenAPI, коннектор папки;
  фронтенд — без новых компонентных тестов, поведение покрыто e2e (mobile + существующие 81).
