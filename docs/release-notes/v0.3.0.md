# Release notes — v0.3.0

Ветка `v0.3.0` от `v0.2.0`. Сквозные отчёты, светофоры и статусы по уровням сотрудников: статус компании сверху вниз по показателям подразделений — финансовым, операционным и вычисляемым из данных служб — со свёрткой по структуре, объяснением статуса и отбором под доступ каждого сотрудника, от первого лица до рядового. Миграция `0015_reports` только добавляет таблицы; доступ пользователей не меняется, откат поддерживается, настраивать ничего не нужно. Решение — ADR-0010 (принято).

## Для сотрудников

- **«Сквозной отчёт»** — новый пункт меню для всех: статус вашей области за месяц крупно, «Почему такой статус» — какие показатели в каких подразделениях его определили, подразделения по статусам, предупреждение о незаполненных показателях, заметки «под контролем», строка «Ваш доступ: …» и какие классы данных скрыты.
- **Матрица «подразделения × показатели»**: цвет ячейки — статус, значение и стрелка изменения к прошлому месяцу, подсказка с целью, отклонением, источником и комментарием, «Нет данных» для пропусков, статус строки, замок «детализация недоступна»; фильтры по статусу и «Только с нарушениями».
- **Оргсхема статусов** — карточки структуры, окрашенные статусом; **список** — для телефона.
- **Панель подразделения**: путь, объяснение до 20 причин, показатели с трендом за 12 месяцев и целью, вложенные подразделения, переходы к дашбордам и реестрам служб (по правам), «Открыть ветку».
- **Статус по доступным показателям**: показатели недоступных классов (например, денежные для рядового сотрудника) не показываются нигде и не влияют на видимый статус — «Статус по N доступным показателям».
- **Отметка «под контролем»** — руководитель подразделения отмечает статус за месяц с комментарием; расчётный статус не меняется.
- **«Ввод показателей»** — таблица подразделения × показатели за месяц: значение, цель, комментарий; сохраняются только изменённые ячейки, ошибки — у ячеек; обязательные незаполненные ячейки выделены. Загрузка Excel или CSV с планом (проверка → применение) и шаблон CSV по форме.
- **PDF сквозного отчёта** (при праве на выгрузку) и **карточка статуса** вашей области на «Обзоре».
- «Мой доступ»: глубина детализации и финансовые показатели теперь действуют — в сквозном отчёте.

## Для администраторов

- **«Показатели»** (`/admin/indicators`): каталог по классам данных — источник (вводится службой-владельцем или вычисляется из данных служб), правило светофора (пороги или отклонение от цели) с предпросмотром и проверкой значения, свёртка (сумма, среднее, без свёртки), типы уровней, где значение ожидается, активность; удаление показателя со значениями — после подтверждения.
- **Подразделения служб** — к какому подразделению структуры относятся показатели техподдержки, партнёрств и службы персонала (по умолчанию — по кодам TECH, PROJ, HR).
- **Полномочие «Ведёт сквозные отчёты»** (`reports.manage`): каталог, ввод значений любой службы во всех подразделениях, заметки о статусе любого подразделения.
- **Права ввода**: уровень «Ввод данных» к службе-владельцу показателя (в том числе к службе без дашборда — «Финансовая служба», «Аппарат генерального директора») в своей области структуры.
- **Доступ по уровням**: вершины отчёта — область пользователя; глубина детализации — сколько уровней ниже перечисляется (глубже — только в итогах); классы данных — какие показатели вообще передаются; исходные записи и выгрузка — ссылки на реестры и PDF.
- Журнал изменений: показатели, значения и загрузки, заметки, подразделения служб.
- Демо-стенд: каталог из 14 показателей, значения за 12 месяцев (последний — июль 2026) с красными и жёлтыми случаями, пропуск «Выполнение плана работ» Службы маркетинга, заметка «под контролем» Технической службы; `tech_dir` вводит операционные показатели своего направления.

## API

- Новое: `/api/reports/scorecard?period=&root=`, `/api/reports/units/{id}?period=` (тренд за 12 месяцев), `/api/reports/periods`, `/api/reports/summary` (карточка «Обзора»), `/api/reports/meta`; каталог `GET/POST/PATCH/DELETE /api/reports/indicators` (`DELETE ?force=` — вместе со значениями); ввод `GET/PUT /api/reports/values`, `POST /api/reports/values/import` (план → применение); `PUT /api/reports/units/{id}/note`; `GET/PUT /api/reports/settings` (подразделения служб); `GET /api/pdf/reports/scorecard`.
- Ответы отчёта уже отобраны под пользователя: показатели недоступных классов в них отсутствуют, подразделения глубже детализации не перечисляются; блок `me` — что пользователь может сделать (`can_export`, `can_enter`, `can_manage`, `note_units`).
- Ошибки — прежний формат `{detail, code, fields}`; новые коды: `unit_out_of_scope`, `entry_forbidden`, `note_forbidden`, `indicator_has_values`, `import_has_errors`.

## Развёртывание

- Миграция `0015_reports` (таблицы `indicators`, `indicator_values`, `unit_status_notes`, `report_revision`) выполняется при старте. **Перед обновлением сделайте резервную копию**; откат — восстановлением копии или `alembic downgrade 0014_org_access` образом 0.3.0. Регламент — `docs/runbooks/upgrade-to-0.3.0.md`.
- Новых переменных окружения и зависимостей нет; в `docker-compose.yml` — тег образа по умолчанию `0.3.0`.
- При первом запуске каталог получает восемь показателей, вычисляемых из данных служб; вводимые показатели (финансовые, операционные) добавьте сами («Руководство администратора», раздел «Показатели и сквозной отчёт»).
- Расчёт отчёта за месяц — один раз на ревизии структуры, данных служб и значений показателей, затем отбор под пользователя без пересчёта; нагрузочная проверка — `docs/performance/load-test-0.3.0.md`.

## Документация

- Руководство пользователя: «Сквозной отчёт» (статус и причины, матрица, оргсхема статусов, панель подразделения, детализация, скрытые показатели, нарушения полноты, «под контролем», PDF, карточка «Обзора», как отчёт выглядит для разных уровней сотрудников) и «Ввод показателей» (форма, загрузка Excel, шаблон); обновлён «Мой доступ».
- Руководство администратора: «Показатели и сквозной отчёт» — каталог, источники, правила светофора с примерами, свёртка, пропуски, права ввода, полномочие, подразделения служб, как доступ определяет отчёт, настройка уровней сотрудников, сценарий «финансовый контролёр»; демо-стенд.
- Руководство по развёртыванию: обновление до 0.3.0; регламент обновления, ADR-0010, CHANGELOG, история версий.
