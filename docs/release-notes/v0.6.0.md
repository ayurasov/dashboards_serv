# 0.6.0 — проектный офис и офис разработки

Реализация ADR-0012 (план docs/plans/v0.6.0-project-office.md, решения владельца 2026-11-21/22).
Тема версии — аналитика проектного офиса и офиса разработки из собственных Jira и GitLab,
строго read-only. Миграции 0017–0021 (5 новых таблиц сырья и службы, откат поддерживается).

## Коннекторы

### GitLab (новый, `kind=gitlab`)

- Действия: проекты (справочник), коммиты (дневной агрегат «день × автор × проект», `with_stats`),
  мерж-реквесты (авторы, ревьюеры, состояния, ключи Jira из названия и ветки), пайплайны
  (день × проект × статус).
- Окна перезаливки (`window_days`, по умолчанию 30), фильтр по группе, пагинация по `X-Next-Page`.
- Токен `read_api` — в секретах (шифрование ADR-0011); адреса — `GITLAB_ALLOWED_HOSTS`.
- Инвентарь эндпоинтов (аудит read-only) — в ADR-0012; изменяющих вызовов в коде нет.

### Jira — сырьё (расширение существующего коннектора)

- Действия «Сырьё: проекты / задачи / трудозатраты»: `jira_projects/issues/worklogs` окнами
  90/180 дней; полная пагинация worklog (догрузка страниц задачи), дедуп в памяти
  (учитывает `autoflush=False`), идентификаторы Jira приводятся к int (строки Server 8.x).
- Прежние агрегаты по JQL (значения показателей) работают без изменений.

## Служба «Проектный офис» (`/projects`)

- **Дашборд**: часы за месяц, план, выполнение плана, ёмкость производственного календаря
  РФ 2025–2027 (предпраздничные 7 ч; корпоративные отличия — `calendar_overrides`; вне
  справочника — предупреждение), задач решено, lead time p50/p90, коммиты и успешность CI
  за 4 недели; селектор месяца в адресе.
- **Проекты × часы**: факт / прошлый месяц / план — план редактирует менеджер службы
  (`project_hour_plans`; 0 — удалить; журнал изменений).
- **Люди месяца** и **Сопоставления**: авто по e-mail (`users.email`, без регистра) + справочник
  исключений `external_identities` (CI-бот, другая почта, несколько учёток); несопоставленные
  авторы — с часами Jira и коммитами GitLab.
- **Реестры** `/projects/issues` и `/projects/mrs`: фильтры в адресе, пагинация; связка
  «задача → код» — счётчик MR у задачи и окно её реквестов (состояние, автор, время ревью).

## Сквозной отчёт

- Вычисляемые показатели из сырья: `po.hours` (часы по подразделениям сотрудников с веткой),
  `po.lead_time` (медиана решения, уровень компании), `po.overdue_share` (>14 дн. до хранения
  срока). Единица службы по умолчанию — TECH, настраивается как у остальных служб.

## Подписка и лента

- **Почтовая подписка** (`status_subscriptions`): вкл/выкл в профиле; воркер раз в сутки пишет
  письмо о «критичных» подразделениях области (до 20 строк, без дублей за день); SMTP —
  `SMTP_HOST/PORT/USER/PASSWORD/FROM/TLS`; без SMTP — пометка «отправка выключена»,
  подписки сохраняются и заработают при появлении SMTP.
- **Лента «Что изменилось с прошлого входа»**: `user_sessions.prev_login_at` (мигр. 0021) →
  `/api/auth/changes` → блок на «Обзоре»; события — применённые и ожидающие «Входящие»
  за 14 дней; справочники, права и входы — шум, не попадают (семантика плана 0.5.0).
