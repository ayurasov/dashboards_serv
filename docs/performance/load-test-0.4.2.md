# Нагрузочная проверка 0.4.2 — smoke

0.4.2 не меняет серверный код запросов (интерфейс, доступность, эксплуатация; единственная
фоновая запись — файл-сердцебиение планировщика раз в такт). Поэтому полная методика
[отчёта 0.4.0](load-test-0.4.0.md) (профили 250/500/1000 пользователей, 6 минут) не повторялась —
выполнен короткий smoke-прогон для подтверждения отсутствия регресса и ошибок.

## Условия прогона

| Параметр | Значение |
| --- | --- |
| Профиль | 100 пользователей, ramp 10/с, 2 минуты (`loadtest/locustfile.py`, `--csv results/u100_smoke`) |
| Стенд | прод-стенд сервера 192.168.2.129 (`dashboards` 0.4.2, PostgreSQL, демо-данные) |
| Загрузка хоста | **совместная**: рядом работают 40+ контейнеров SRM2 и CI-раннеры, load average 5–7 — это НЕ чистый стенд из отчёта 0.4.0 |

## Результаты

| Метрика | Значение |
| --- | --- |
| Запросов / ошибок | 2146 / **0** |
| Медиана | 21 мс |
| p90 / p95 / p99 | 130 / 390 / 850 мс |
| CPU контейнера `app` за прогон | ~1,5 % (узким местом не является) |

Медиана и отсутствие ошибок соответствуют базовой линии; p95 выше отчёта 0.4.0 (63 мс при
1000 пользователей) из-за совместной загрузки хоста соседними стеками — приложение при этом
не потребляет ресурсов. До содержательных выводов о p95 полный прогон нужно повторить на
свободном хосте по методике 0.4.0.

## Вывод

Регресса нет: ошибки отсутствуют, медиана в норме, ресурсы приложения не растут.
Для сравнимых с 0.4.0 цифр p95 — повторить полный профиль на выделенном хосте.
