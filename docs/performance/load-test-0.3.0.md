# Нагрузочное тестирование версии 0.3.0: 1000 пользователей

- Дата: 01.11.2026
- Версия: 0.3.0 (сквозные отчёты)
- Стенд, настройки и методика — как для 0.1.0 и 0.2.0 (`docs/performance/load-test-0.1.0.md`, ADR-0006); сводная статистика — `docs/performance/load-test-0.3.0/`

## Вывод

**Версия 0.3.0 выдерживает 1000 одновременных пользователей на 4 ядрах без ошибок сервера**, сквозной отчёт — один из самых быстрых запросов: отчёт за период рассчитывается один раз на ревизии структуры, данных служб и значений показателей, а под каждого пользователя только отбирается (область, глубина, классы данных).

| Пользователей | Запросов/с | p50 | p95 | p99 | Ошибки |
| ---: | ---: | ---: | ---: | ---: | --- |
| 1000 | 144 | 20 мс | 69 мс | 180 мс | ошибок сервера нет; 5 сбросов соединения на 41,8 тыс. запросов |

Значения — медианы по окнам статистики Locust в установившемся режиме; в отдельных окнах p95 доходил до 1,1 с — на той же машине в это время работали другие процессы (сборка документации и снимки экрана).

## Что добавлено в сценарий

- «Обзор» запрашивает карточку статуса (`/api/reports/summary`).
- Страница «Сквозной отчёт» (вес 6): периоды, отчёт и панель случайного видимого подразделения.
- Пользователи всех уровней демо-стенда: высшее руководство видит компанию и направления, сотрудник — только своё подразделение без финансовых показателей.

| Запрос | Запросов | p50 | p95 |

Сбросы соединения (`ConnectionResetError`) — закрытие keep-alive соединения процессом, который перезапускается по `GUNICORN_MAX_REQUESTS`; браузер повторяет такие запросы сам, генератор нагрузки — нет (как в 0.1.0).

## Разгон

Пока входят все 1000 пользователей (10 входов в секунду), медиана входа — 5,8 с: проверка пароля (bcrypt) занимает процессор. Без нагрузки вход — 0,33 с, как в предыдущих версиях. Рекомендации по массовому входу — в отчёте 0.1.0.
