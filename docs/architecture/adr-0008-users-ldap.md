# ADR-0008. Пользователи, вход по учётной записи домена (LDAP) и синхронизация с Active Directory

- Статус: принято
- Дата: 2026-11-01
- Версия: 0.2.0
- Источник: подход todo-planner (ADR-0045, ADR-0051 там) с доработками
- Связано: ADR-0003 (сессии), ADR-0007 (структура), ADR-0009 (модель доступа 2.0)

## Решение

### Пользователь

- Статусы: «Активен», «Отключён» и вычисляемый «Без доступа» (локальная учётная запись без пароля — например, загружена списком); «Выдать доступ» — временный пароль или вход по домену.
- `auth_source` — `local` или `ldap`; `auth_external_id` (objectGUID / entryUUID, уникален), `auth_linked_at`; у доменной учётной записи нет локального пароля, «Сбросить пароль» переводит её на пароль системы.
- Администратор не может отключить себя и снять с себя роль; последний активный администратор защищён (как в 0.1.0).
- Список: поиск (ФИО, логин, email, должность, подразделение), фильтры роль · статус · подразделение (в том числе «Без подразделения») · профиль доступа · способ входа; сводка «всего · активных · отключено · без доступа · по домену · администраторов».

### Вход по домену (LDAP)

Настройки — переменные окружения `AUTH_LDAP_*` (секреты в API и интерфейс не попадают); ldap3.

1. Служебная привязка (`AUTH_LDAP_BIND_DN`) или анонимная, поиск по фильтру `AUTH_LDAP_USER_FILTER` с экранированием логина (`escape_filter_chars`), ровно одна запись — иначе отказ.
2. Привязка от имени DN найденной записи с паролем пользователя (DN не собирается из логина).
3. Отключённые в AD (`userAccountControl & 2`) не входят.
4. Сопоставление: `auth_external_id`, затем `external_id` из синхронизации с AD, затем email (уникальный). Логин для сопоставления не используется.
5. Первый вход без учётной записи — создание, если `AUTH_LDAP_CREATE_USERS` = `active` / `inactive`; профиль доступа — по группам каталога (`AUTH_LDAP_GROUP_PROFILES`: «DN группы = ключ профиля», первое совпадение), иначе `AUTH_LDAP_DEFAULT_PROFILE`. Группа `AUTH_LDAP_ADMIN_GROUP` даёт роль администратора только при создании.
6. Порядок входа: каталог подтвердил пароль → вход; иначе локальная учётная запись не из домена с совпавшим паролем; доменная учётная запись при недоступном каталоге — 503 «Сервер домена не отвечает»; пароль доменной учётной записи в системе не проверяется никогда.

Доработки относительно todo-planner: StartTLS для `ldap://` (`AUTH_LDAP_START_TLS`), проверка подключения из интерфейса («Проверить подключение» и «Проверить вход» для логина без сохранения), профили по группам.

### Синхронизация с Active Directory

`AD_SYNC_*` (по умолчанию — те же адрес и учётные данные, что у входа), постраничное чтение, путь подразделения из атрибутов (`company, division, department`) или из OU, руководитель из `manager`, руководители подразделений определяются по подчинённым. Проверка → план (создать подразделения, создать/обновить/отключить сотрудников, ошибки) → применение одной транзакцией. Отключаются только сотрудники, пришедшие из AD; включать синхронизация не может. Запуск — из интерфейса и `python -m app.cli org-sync --ad [--apply]` для планировщика.

## Последствия

- Email доменной учётной записи считается подтверждённым каталогом: привилегированные локальные учётные записи держите на адресах вне каталога.
- Профиль доступа из групп назначается при создании; дальше доступ настраивает администратор (ADR-0009).
