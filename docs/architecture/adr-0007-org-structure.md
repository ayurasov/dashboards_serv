# ADR-0007. Структура компании: подразделения, руководители, представления, перенос

- Статус: принято
- Дата: 2026-11-01
- Версия: 0.2.0
- Источник: подход todo-planner (ADR-0044, ADR-0046, ADR-0051 там) с доработками
- Связано: ADR-0008 (пользователи и вход по домену), ADR-0009 (модель доступа 2.0)

## Контекст

В 0.1.0 подразделения — плоский справочник «название + код» и связь «пользователь — подразделения» для ограничения реестра службы персонала. Для сквозных отчётов и разграничения доступа по уровням нужна настоящая структура: дерево уровней, руководители, подчинённость, численность — та же модель, что в todo-planner, где она проверена на структурах в тысячи сотрудников.

## Решение

### Данные

- `departments` становится деревом: `parent_id` (RESTRICT), `kind` (тип уровня из настроек), `sort_order`, `code` (необязательный, уникальный), `external_id`, `org_source` (`manual` · `import` · `csv` · `ad`), `name_key` — нормализованное имя (без регистра и лишних пробелов). Имена уникальны среди соседей — частичными уникальными индексами `(parent_id, name_key)` и `(name_key) WHERE parent_id IS NULL` (в todo-planner проверялось только в коде, и параллельные запросы могли создать дубль).
- `department_heads` — руководители подразделения с признаком основного (`is_primary`, не больше одного — частичный уникальный индекс).
- У пользователя: `department_id` — основное подразделение (SET NULL), `manager_id` — явный руководитель, `reports_to_none` — «первое лицо», `external_id`, `org_source`.
- Связь «пользователь — подразделения» 0.1.0 переносится: одно подразделение — основное; несколько — первое основное, остальные — дополнительные подразделения области доступа (ADR-0009).
- `app_settings` — настройки приложения «ключ — JSON»: типы уровней (`org_unit_kinds`), предел вложенности (`org_max_depth`), вид оргсхемы по умолчанию (`org_default_view`).
- `org_revision` — ревизия структуры (как ревизии данных служб): увеличивается в транзакции любого изменения подразделений, руководителей и полей подчинения пользователей. Снимок структуры в памяти процесса перестраивается только при смене ревизии.

### Правила (как в todo-planner)

- **Непосредственный руководитель**: «первое лицо» — никого; иначе явный руководитель (активный); иначе подъём по дереву от основного подразделения (а без него — от родителя первого руководимого) до первого уровня, где сотрудник не руководитель: его основной (или первый по алфавиту) активный руководитель.
- **Основное подразделение** для численности: `department_id`, а без него — руководимое (сначала основное). В остальных руководимых уровнях человек показывается «руководитель, числится в …».
- Запреты: вложить подразделение в себя или в дочернее, сделать сотрудника руководителем самому себе или своему подчинённому (цикл), превысить предел вложенности, повторить имя у соседей, удалить подразделение с дочерними; в сообщениях — что сделать.
- Удаление подразделения записывается в журнал изменений (в todo-planner не записывалось), сотрудники остаются без подразделения.
- Признак основного руководителя не теряется при изменении состава руководителей (в todo-planner терялся).

### Представления

«Структура компании» — четыре вида, выбор сохраняется в адресе и у пользователя:

1. **Оргсхема** — карточки уровней с линиями подчинения: тип цветом, основной руководитель, штат уровня и численность ветки, «N подразделений», «Вы здесь», путь к выбранному, масштаб и «вписать», перетаскивание, ориентация, компактный режим, нижний уровень столбиком.
2. **Люди** — схема по непосредственному руководителю: прямые подчинённые и вся ветка.
3. **Дерево** — список уровней с сотрудниками, руководители первыми.
4. **Таблица** — путь, тип, уровень, руководитель, штат, ветка; сортировка, фильтр по типу, выгрузка в Excel.

Общие: поиск по уровням и людям, «Уровней: 1…N», «Развернуть / Свернуть», «Где я». Боковая панель уровня (путь, руководители, вложенные, сотрудники) и сотрудника (руководитель с источником, цепочка, подчинённые). Структуру видят все вошедшие пользователи — она не содержит данных служб; отключённых сотрудников видит только администратор.

Администрирование «Подразделения» — дерево с численностью и руководителями, добавление вложенного уровня, изменение (название, «входит в», тип, порядок), руководители с основным, удаление; «Типы уровней и вложенность».

### Перенос структуры и сотрудников

Все виды загрузки работают в два шага: **проверка** (план без записи в базу: что создастся, изменится, ошибки) и **применение** одной транзакцией; при ошибках ничего не записывается.

- **Структура** — JSON `dashboards.org-structure` v1: настройки структуры и подразделения (путь, тип, порядок, код, руководители по email). Подразделения сопоставляются по пути, отсутствующие в файле не удаляются, руководители только добавляются.
- **Сотрудники** — выгрузка в Excel, CSV (UTF-8 с BOM, «;») и JSON; загрузка с разбором различий: значение системы, из файла или своё; пустое в файле не стирает; сопоставление по email. Профиль доступа — по названию.
- **Быстрая загрузка списком** — CSV/Excel со столбцами «email; ФИО; Подразделение (путь через /); Должность; Руководитель (email); Руководит».
- **Active Directory** — ADR-0008.

## Не переносится из todo-planner

Функциональное подчинение и замещения служат поручениям задач; термины структуры («отдел», «сотрудник») — в дашбордах не требуются. Добавляются, когда понадобятся доступу (например, замещение руководителя на время отпуска).

## Последствия

- Область доступа «своя ветка / своё подразделение» (ADR-0009) вычисляется по снимку структуры без запросов к базе.
- Реестр службы персонала сопоставляет подразделение записи с названием или кодом подразделения структуры.
