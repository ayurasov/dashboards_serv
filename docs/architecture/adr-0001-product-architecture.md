# ADR-0001. Архитектура продукта 0.1.0: сервер FastAPI, интерфейс Vue, один образ

- Статус: принято
- Дата: 2026-11-01
- Версия: 0.1.0
- Связано: ADR-0002 (база данных), ADR-0003 (сессии), ADR-0004 (доступ), ADR-0005 (интерфейс)

## Контекст

До 0.1.0 приложение было набором быстро собранных частей: FastAPI с роутерами, в которых смешивались запросы к базе, проверка прав и расчёты; отдельное Flask-приложение `tp-report` для отчёта техподдержки; интерфейс на Vue с двумя библиотеками графиков (ECharts и Chart.js). Общих правил не было: каждая служба по-своему проверяла права (а чтение данных службы персонала и PDF не проверялись вовсе), по-своему хранила настройки светофора, по-своему оформляла страницы. Сборка ломалась из-за повреждённого `package-lock.json`, тесты шли 4,5 минуты и часть падала.

Требования к 0.1.0: превратить прототип в продукт — зрелая работа с базой, единая модель доступа и единый интерфейс, тесты и документация, предсказуемое развёртывание; при этом сохранить все данные и функции прежней версии.

## Решение

### Слои сервера (`backend/app`)

| Слой | Каталог | Содержимое |
| --- | --- | --- |
| Ядро | `core/` | конфигурация (pydantic-settings), подключение к базе, миграции, безопасность, единый формат ошибок, журнал, ограничение частоты |
| Модели | `models/` | SQLAlchemy 2 с аннотациями `Mapped`, по файлу на предметную область (`core`, `hr`, `tp`, `partnerships`) |
| Схемы | `schemas/` | Pydantic: входные (`extra="forbid"`, обрезка пробелов) и выходные |
| Сервисы | `services/` | расчёты и правила: аналитика служб, светофор, доступ, журнал, импорт и экспорт, PDF, справочники, демо-данные |
| API | `api/` | роутеры FastAPI (тонкие), зависимости проверки прав, загрузка и выдача файлов |
| Обслуживание | `cli.py` | `migrate`, `demo-data`, `create-admin`, `reset-password`, `check-schema`, `cleanup-sessions` |

Роутер только разбирает запрос, вызывает проверку прав через зависимость `require_service(служба, уровень)` и сервис, пишет журнал и фиксирует транзакцию. Справочники (службы, метрики, правила по умолчанию, палитры) описаны в коде (`services/registry.py`) и синхронизируются при старте одним процессом.

### Прототип `tp-report` удалён

Его функции полностью перенесены в службу «Техническая поддержка», исходные данные — в `backend/app/data/demo`.

### Один образ, один процесс-менеджер

Интерфейс собирается стадией Node и раздаётся тем же сервером (`/assets` — статика, остальные пути — `index.html`). В образе работает gunicorn с воркерами uvicorn (`uvicorn-worker`); перед запуском `docker-entrypoint.sh` выполняет `python -m app.cli migrate`. В `docker-compose.yml` — приложение и PostgreSQL 16.

### Версия продукта

Версия хранится в `backend/app/__init__.py` (`__version__`) и `frontend/package.json`; отдаётся `/api/version` и `/api/health`, показывается в интерфейсе («О программе», «Что нового»), проверяется тестами (`versions.test.js`) и сборщиком руководств. Ветки разработки — `vX.Y.Z`.

## Последствия

- Добавить службу — значит добавить запись в реестр служб, модели и миграцию, сервис, роутер с `require_service`, экраны и пункты меню; общие механизмы (доступ, светофор, журнал, раскладки, PDF, импорт) готовы.
- Прежние адреса страниц перенаправляются на новые (`/registry` → `/hr/registry` и т. д.).
- Сервер не хранит состояние в памяти, кроме счётчика неудачных входов, поэтому процессы и экземпляры взаимозаменяемы.
