# ADR-0002. База данных: PostgreSQL, Alembic как единственный источник схемы, миграция 0012

- Статус: принято
- Дата: 2026-11-01
- Версия: 0.1.0
- Связано: ADR-0001

## Контекст

В базах прежних версий схема расходилась с моделями: при старте вызывались `create_all()` и самописное добавление столбцов, миграции 0001–0011 покрывали только часть таблиц и не совпадали с моделями (сравнение autogenerate давало 60+ расхождений). Существовало минимум три состояния рабочих баз:

1. Docker-установка: история Alembic до `0011_naumen_tickets` плюс таблицы, созданные `create_all()`;
2. локальный запуск по прежнему README: таблицы от `create_all()`, истории Alembic нет;
3. новая пустая база.

Кроме того: в SQLite не включалась проверка внешних ключей (каскадное удаление не работало), год и неделя отчёта ТП хранились числами с плавающей точкой без уникальности, номер заявки Naumen не был уникален, настройки светофора ТП лежали JSON-строкой в отдельной таблице, роли и уровни доступа смешивались.

## Решение

### PostgreSQL — основная СУБД

Драйвер psycopg 3, пул соединений с `pool_pre_ping`, `DB_POOL_SIZE` на процесс. SQLite остаётся для разработки и небольших стендов: включаются `foreign_keys`, WAL и юникодная функция `lower()` (встроенная понижает только латиницу — поиск по кириллице без учёта регистра не работал).

### Только Alembic

Приложение не создаёт таблиц. `app/core/migrate.py`:

- база без истории Alembic, но с таблицами прежней версии, помечается ревизией `0011_naumen_tickets`;
- старая цепочка 0001–0011 прогоняется без конвенции имён ограничений (с ней она конфликтует на PostgreSQL), начиная с 0012 — с конвенцией;
- на PostgreSQL миграции выполняются под `pg_advisory_lock`, поэтому несколько одновременно стартующих контейнеров безопасны.

### Миграция `0012_v0_1_0_schema` — перестройка с переносом данных

Для каждой таблицы создаётся каноническая версия, данные переносятся с чтением только тех столбцов, которые есть в старой таблице, старая таблица удаляется. Таблицы с совпадающим именем сначала переименовываются в `_legacy_*`; их индексы (на PostgreSQL — и последовательности) переименовываются или удаляются, чтобы освободить общие имена. Преобразования:

| Было | Стало |
| --- | --- |
| `month_records`, `employee_events`, `metric_definitions`, `metric_values`, `notes`, `benchmarks` | `hr_months`, `hr_employee_events`, `hr_metric_definitions`, `hr_metric_values`, `hr_month_notes`, `hr_targets` |
| `tp_report_rows` (год и неделя — float) | `tp_weekly_reports`: год и неделя — integer, уникальная пара, CHECK недели 1–53; дубли схлопываются |
| `tp_settings.traffic_rules` (JSON) | строки общей `traffic_light_rules` со `service_key = 'tech'` |
| `dashboard_modules` | справочник `services` (внешний ключ для доступа, настроек, правил) |
| `user_service_access` (read/edit/edit_metrics/admin) | `service_access` (viewer/editor/manager + `department_scope`) |
| роли admin/hr_head/viewer/department_viewer | роли admin/user + доступ к службе персонала |
| `user_dashboard_preferences`, `dashboard_widgets`, `audit_logs` | `dashboard_layouts`, `custom_dashboard_widgets`, `audit_log` |
| — | `user_sessions`, `service_settings`, `data_imports` |

Значения метрик без описания сохраняются: создаётся выключенная метрика. Откат 0012 запрещён (восстановление из резервной копии).

### Конвенция и ограничения

Имена `pk_`, `uq_`, `ix_`, `fk_`, `ck_` по единой конвенции; внешние ключи с `ON DELETE CASCADE / SET NULL`; CHECK для ролей, уровней доступа, направлений светофора, цветов, месяцев и недель; индексы под фильтры реестров и журнала.

### Проверки

Тесты (`tests/test_migrations.py`): единственная голова цепочки; после `upgrade` на пустой SQLite и PostgreSQL сравнение autogenerate с моделями пустое; обновление базы `create_all()` из фикстуры прежней версии и базы со старой цепочкой и данными; отказ отката. CI поднимает PostgreSQL 16.

### Перенос SQLite → PostgreSQL

`backend/scripts/sqlite_to_postgres.py` копирует все таблицы в порядке зависимостей и выставляет последовательности; без `--force` отказывается, если в PostgreSQL уже есть данные служб.

## Последствия

- Любое изменение моделей требует миграции; тест сверки схемы не даст их разойтись.
- Обновление прежних установок — одна команда, но резервная копия перед ним обязательна.
