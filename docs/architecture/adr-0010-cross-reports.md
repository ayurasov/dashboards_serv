# ADR-0010. Сквозные отчёты, светофоры и статусы по уровням сотрудников

- Статус: предложено (проектирование начато в 0.2.0, реализация — 0.3.0)
- Дата: 2026-11-01
- Связано: ADR-0007 (структура компании), ADR-0009 (модель доступа 2.0)

## Контекст

Дашборды 0.1.0 — по службам: каждый показывает свою предметную область целиком. Руководству нужна единая картина компании «сверху вниз»: общий статус, из чего он складывается, где проблема — с возможностью раскрыть уровень структуры и показатель до нужной глубины. Рядовым сотрудникам — статус своего подразделения без денежных показателей. Глубина и состав видимого у каждого свои (ADR-0009).

## Решение

### Показатели

Каталог показателей (`indicators`): ключ, название, единица, класс данных (операционный · персональный · финансовый), направление (больше — лучше / меньше — лучше), периодичность (месяц · квартал), способ свёртки по структуре (сумма · среднее · взвешенное · худший статус), правило светофора (пороги или отклонение от цели), владелец (служба), источник:

- **из данных служб** — вычисляется: текучесть и численность (персонал, по подразделению записи), нагрузка и решение заявок (техподдержка), доля партнёрств с зелёным статусом (партнёрства);
- **ввод по подразделениям** — значение и цель за период вносит ответственный подразделения (уровень «ввод данных» к службе-владельцу) или загружается из Excel; так приходят финансовые показатели: выручка, затраты, ФОТ, исполнение бюджета.

### Статусы и свёртка

- Статус показателя в подразделении за период — светофор по правилу: зелёный · жёлтый · красный · нет данных.
- Статус подразделения — свёртка статусов его показателей и дочерних подразделений: по умолчанию худший значимый, с весами показателей — взвешенный; «нет данных» не ухудшает, но показывается долей.
- Статус компании — свёртка верхнего уровня. Каждый статус объясним: «красный из-за: текучесть в Коммерческой службе 14 % при цели 8 %».
- Ручной статус с комментарием (руководитель может пометить «под контролем» до следующего периода) — следующий шаг.

### Провал вглубь

- Экран «Сквозной отчёт»: вершина области пользователя → дочерние уровни структуры → показатели уровня → динамика показателя → исходные данные службы (если есть право на исходные записи и доступ к службе).
- Глубина раскрытия ограничена `drill_depth` от вершины области; ниже предела — только свёрнутый статус без раскрытия.
- Показатели класса, недоступного пользователю, не показываются и **не участвуют в объяснении** статуса (свёрнутый статус остаётся, чтобы не раскрывать значение через цвет — настраивается: «скрывать влияние недоступных показателей»).
- Виды: плитки статусов по уровням (светофорная матрица «подразделения × показатели»), дерево статусов на оргсхеме (цвет карточки), тренд статуса по периодам.

### Уровни сотрудников (по профилям ADR-0009)

| Профиль | Что видит |
| --- | --- |
| Высшее руководство | Компания и направления, все классы данных, без исходных записей; глубина расширяется лично |
| Руководитель направления | Своё направление до уровня отделов, все классы данных, исходные записи |
| Руководитель подразделения | Своя ветка целиком, без финансовых показателей |
| Сотрудник | Статус своего подразделения, только операционные показатели, без раскрытия и выгрузки |

### Хранение (проект)

`indicators`, `indicator_rules`, `indicator_values (indicator_id, department_id, period, value, target, comment, source, entered_by)`, `status_snapshots` (рассчитанные статусы за период для быстрых ответов и истории; пересчёт по ревизии данных), `status_overrides` (ручной статус с комментарием и сроком).

### Открытые вопросы

- Закрепление показателей за уровнями: все показатели на всех уровнях или набор по типу уровня (компания · дирекция · отдел).
- Отчётный период и закрытие периода (фиксация значений).
- Веса показателей в свёртке и согласование их с руководством.
