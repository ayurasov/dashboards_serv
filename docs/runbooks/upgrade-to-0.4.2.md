# Обновление до 0.4.2

Аудит интерфейса: понятность показателей, доступность, устойчивость тестов и эксплуатационные улучшения.
**Миграций нет** — схема базы не меняется; переменные окружения и настройки — прежние.

## Изменения, которые заметит эксплуатация

- `worker` получил healthcheck: планировщик пишет файл-сердцебиение `/tmp/worker-heartbeat`
  (переопределяется переменной `WORKER_HEARTBEAT_FILE`, пусто — файл не пишется и healthcheck нужно
  вернуть `disable: true` в override-файле). После обновления `docker compose ps` покажет состояние
  `worker` (healthy), а не только «Up».
- Коннектор «Папка „Входящие“» при отсутствии прав на папку теперь отвечает понятным сообщением
  «Нет доступа к папке…» — если такое встречалось, это признак проблем с правами, а не «внутренняя ошибка».

## Порядок обновления

```bash
git fetch && git checkout v0.4.2          # или ваш способ доставки кода
docker compose build
docker compose up -d
curl -s http://127.0.0.1:8000/api/health  # статус ok, схема current=head
docker compose ps                         # app, db, worker — healthy
```

Обновление с 0.4.0/0.4.1 — без промежуточных шагов. С версий до 0.4.0 — сначала
[обновление до 0.4.0](upgrade-to-0.4.0.md).

## Проверка после обновления

- `docker compose logs worker --tail 3` — «Планировщик запущен»;
- экран «Входящие → Папка» — отметка планировщика свежая;
- «Обзор»: карточки служб упорядочены по критичности, под заголовком — легенда «значок — статус,
  стрелка — динамика».

## Откат

Образ предыдущей версии сохраняется локально до очистки. `git checkout v0.4.1`,
`APP_VERSION=0.4.1 docker compose up -d` — схема и данные совместимы в обе стороны.
