# Обновление до 0.6.0

Проектный офис и офис разработки (ADR-0012): коннекторы GitLab и сырьё Jira (read-only),
служба «Проектный офис», показатели сквозного отчёта из сырья, подписка на критичные статусы,
лента «что изменилось». **Миграции 0017–0021** (5 новых таблиц; откат поддерживается),
новые переменные окружения — только для новых возможностей.

## Переменные окружения (все — новые, можно не задавать)

| Переменная | По умолчанию | Что делает |
| --- | --- | --- |
| `GITLAB_ALLOWED_HOSTS` | пусто (любые) | Разрешённые узлы коннектора GitLab |
| `SMTP_HOST` | пусто | Ретранслятор писем подписки; пусто — отправка выключена |
| `SMTP_PORT` / `SMTP_USER` / `SMTP_PASSWORD` | 25 / пусто | Аутентификация SMTP |
| `SMTP_FROM` / `SMTP_TLS` | `dashboards@company.ru` / false | От кого и STARTTLS |

## Порядок обновления

```bash
git fetch && git checkout v0.6.0
docker compose build
docker compose up -d                      # применятся миграции 0017–0021
curl -s http://127.0.0.1:8000/api/health  # статус ok, версия 0.6.0, схема current=head=0021_...
```

Обновление с 0.5.x — без промежуточных шагов. Первая загрузка демо-данных на новой базе
создаёт и справочники новой службы.

## После обновления

1. **Права**: служба «Проектный офис» по профилям («Высшее руководство» видит её сразу);
   остальным выдайте уровень («Администрирование → Пользователи»). Единицу службы сквозного
   отчёта проверьте в «Ввод показателей → Настройки» (по умолчанию TECH).
2. **Подключения** (администратор, «Интеграции»): GitLab — адрес, токен `read_api`, при
   самоподписанном сертификате снимите «Проверять сертификат»; Jira — тип «Server / Data Center»
   с логином и паролем (basic) или персональным токеном. Запустите действия по порядку:
   «Сырьё: проекты» → «задачи» → «трудозатраты» (GitLab: «Обновить проекты» → остальные).
3. **Расписания** подключений: окно 30 дней перезаливает ночью; для первого запуска можно
   задать `window_days` больше (до 365).
4. **Сопоставления**: на дашборде службы нажмите «Сопоставления» — несопоставленные авторы
   (CI-боты, личные почты) свяжите с сотрудниками; часы несопоставленных в людей не попадают.
5. **Подписка** (по желанию): задайте `SMTP_HOST` в `.env`, перезапустите (`docker compose
   up -d`); пользователи включают письмо в профиле.

## Проверка после обновления

- «Обзор» → служба «Проектный офис»: часы, проекты, люди; реестры `/projects/issues`,
  `/projects/mrs` открываются с фильтрами;
- сквозной отчёт: показатели po.hours / po.lead_time / po.overdue_share вычислены из сырья;
- `docker compose logs worker | grep -i подписк` — ошибок SMTP нет (или честная пометка).

## Откат

`git checkout v0.5.0`, `APP_VERSION=0.5.0 docker compose up -d` — таблицы сырья останутся,
приложение их не читает; при необходимости `docker compose exec app python -m app.cli
migrate --down 0016_integrations` сносит таблицы 0017+ (данные Jira/GitLab будут потеряны).
