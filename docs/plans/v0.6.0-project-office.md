# План 0.6.0 — проектный офис и офис разработки: Jira, Confluence, GitLab

> Решения владельца 2026-11-21: инстансы и ответы на открытые вопросы — раздел «Решения» в конце.

Направление задано владельцем продукта 2026-11-21: развивать аналитику в сторону проектного офиса
и офиса разработки — тянуть статистики по рабочим часам и проектам из Jira, публиковать/читать
Confluence, добавлять метрики GitLab. Настоящий документ — концепт для обсуждения; оценки после
прототипа коннекторов.

Техническое решение — [ADR-0012](../architecture/adr-0012-project-office-data.md): таблицы сырья,
действия коннекторов, сопоставление людей, производственный календарь, этапы.

## Что подтвердили read-only пробы (2026-11-21, с сервера стенда)

- **Jira Server 8.3.5** — `POST /rest/api/2/search` пагинацией `startAt`, поля `worklog`/`timespent`,
  basic-авторизация; аккаунт видит проекты (AP1C, CRM1C, AIS, AIE, AC…), поиск и worklog своих задач.
- **Confluence** — `/rest/api/space` отвечает той же учётной записью.
- **GitLab** — API v4; без токена доступен список публичных проектов, для остальных нужен `read_api`-токен
  (см. открытый вопрос 1).

## Что уже есть (опора)

- **Коннектор Jira** (`app/integrations/connectors/jira.py`): Cloud и Server, поиск по JQL c
  подстановками `{month_start}`, `{unit_code}`, `worklogDate` — уже сегодня можно собирать рабочие
  часы агрегатом в показатели сквозного отчёта. Ограничение: сырых данных нет — только значения
  показателей, drill-down до задачи невозможен.
- **Коннектор Confluence**: публикация сквозного отчёта на страницу.
- **Каркас интеграций** (ADR-0011): секреты с шифрованием, проверки до сохранения, расписания,
  журнал запусков, «По Делу»/«Пульс» по ключам — новый коннектор наследует всё это бесплатно.
- **Опыт смежного продукта**: burndown_tool (Монте-Карло, дайджесты) — семантика метрик скорости
  отработана.

## Целевая картина

Новая служба **«Проектный офис»** (registry + доступ по профилям, как у трёх существующих):
дашборд «часы и проекты», реестры задач и активностей, показатели в сквозной отчёт.

### Данные Jira (расширение коннектора: агрегаты → сырьё)

| Что | Зачем |
| --- | --- |
| Проекты (ключ, название, ведущий) | структура проектного офиса, разрезы |
| Задачи: created/resolved, статус, assignee, приоритет, даты | динамика, WIP, просрочки, lead time |
| Worklogs: автор, задача, дата, часы | **рабочие часы по людям/проектам/периодам** — запрос владельца |
| Спринты/эпики (по наличию) | velocity, burndown |

Хранение: таблицы-снапшоты `jira_projects`, `jira_issues`, `jira_worklogs` (+срок хранения как у
входящих); сопоставление `jira_username → сотрудник структуры` — справочник на экране службы.

### Данные GitLab (новый коннектор)

| Что | Метрики |
| --- | --- |
| Проекты, участники | активность по репозиториям и людям |
| Коммиты | частота, авторство по неделям |
| Мерж-реквесты | время ревью, размер диффа, revert rate, доля принятых |
| Пайплайны CI | длительность, успешность, время до зелёного |
| Связка MR ↔ Jira (ключ в названии) | «задача → код → прод» — уникальная сквозная метрика |

### Показатели-кандидаты в сквозной отчёт (проектный офис)

- часы по проектам: факт против плана, доля внутренних задач;
- lead time p50/p90 задач, WIP, доля просроченных;
- время первого ревью MR, медиана ревью-латентности;
- успешность пайплайнов, время восстановления после красного билда (MTTR-CI);
- скорость (story points/спринт) — при наличии оценок в Jira.

## Решения владельца (2026-11-21)

1. **Jira — свой сервер**: `https://jira.almi-partner.ru:8443` (Data Center/Server, не Cloud).
   Доступ по учётной записи; креды — **только в секретах** (шифруются `SECRET_KEY`), использование
   — **строго read-only** (никаких POST/PUT/DELETE в сторону Jira из продукта).
2. **Confluence — свой сервер**: `https://confluence.almi-partner.ru` (тот же принцип: секреты,
   для публикации — отдельное действие с явным подтверждением; чтение — read-only).
3. **GitLab — свой**: `https://gitlab.almi-partner.ru/`, доступ по API-токену. Нужен коннектор.
4. **Сопоставление людей** — по логинам/почтам, они одинаковые во всех системах: Jira/GitLab ↔
   сотрудники структуры сопоставляются автоматически по e-mail, ручной справочник — для исключений.
5. **План часов — из производственного календаря**: плановая ёмкость человека на период =
   рабочие дни × 8 ч (предпраздничные — 7 ч) по встроенному календарю РФ с возможностью
   переопределения (корпоративные переносы); план по проектам — доля ёмкости, заданная вручную.
