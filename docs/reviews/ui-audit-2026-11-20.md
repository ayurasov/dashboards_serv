# Аудит «Дашбордов компании» 0.4.1 — качество, дизайн, документация, вёрстка

Дата: 2026-11-20. Эталон для сравнения — подход todo-planner («По Делу», v1.4.10).
Основа для плана доработок: находки проверены по коду и на работающем стенде; спорные гипотезы
визуального ревью перепроверялись кодом/полными скриншотами, опровергнутые — вынесены в раздел «не дефект».

## Методика

1. **E2E**: штатный Playwright-набор (12 спецификаций, 81 тест) на отдельном экземпляре
   (SQLite, демо-данные, порт 8085) — два прогона + изолированные повторы упавших.
2. **UI-обход**: собственный скрипт (Playwright) — 81 страница × 5 ролей (admin, ceo, tech_dir,
   engineer, hr_head) × светлая/тёмная тема × десктоп 1440 / мобильный 390; на каждой странице
   собирались ошибки консоли, pageerror, HTTP≥400 и горизонтальный overflow; 83 скриншота.
3. **Визуальное ревью**: разбор ключевых экранов (обзор, сквозной отчёт в тёмной теме, HR-дашборд
   полностью и во вьюпорте, мобильный отчёт, логин) моделью зрения + проверка каждого claims по коду.
4. **Статический разбор фронтенда**: tokens.css, base.css, общие компоненты (модалки, тосты,
   таблицы), a11y-метрики, брейкпоинты, состояния.
5. **Аудит документации**: инвентарь docs/ против эталона.

## Сводный вердикт

Продукт архитектурно зрелый и по ряду практик **опережает эталон** (тёмная тема с контраст-тестом,
модальный фокус-трап со стеком, sticky-таблицы из коробки). Слабые места — не в инженерии, а в
**коммуникации смысла** (семантика статусов/стрелок), **мелкой типографике на грани читаемости**
(`--faint`), **дисциплине адаптива** (16 брейкпоинтов) и **честности README** (нет «Ограничений»).
E2e-прогон и обход чистые: 0 ошибок консоли, 0 HTTP-ошибок, 0 горизонтального overflow на 390px.

## Не дефект (проверено, чтобы не гоняться за фантомами)

- «Обрезанные графики» на HR-дашборде — артефакт viewport-скриншота; fullPage показывает оси X
  и месяцы полностью (перепроверено).
- «Контраст приглушённого текста ниже 4.5:1» — для `--muted` опровергнуто тестом
  (`contrast.test.js`, факт 5.27:1); претензия верна только к `--faint` (B1).
- «Нет sticky-шапки таблиц» и «числа не выровнены вправо» — опровергнуто: `base.css:132,144`
  (sticky + `.num` вправо с tabular-nums), sticky-первый-столбец в матрице и вводе показателей.
- «Нет обработки ошибок входа» — есть (экран ошибки входа снят, e2e «неверный пароль» проходит).
- «Радиусы разнобой» — это осознанная шкала токенов 6/10/14px, не разнобой.
