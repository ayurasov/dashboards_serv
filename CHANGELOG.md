# CHANGELOG

## v0.1.0 — 2026-11-01

Первая версия продукта «Дашборды компании». Прототип переработан целиком: сервер на зрелой платформе с PostgreSQL и миграциями, серверные сессии и единая модель доступа к службам, новый интерфейс на собственной дизайн-системе, стартовая страница «Обзор», встроенные руководства и история версий, тесты, CI и документация. Все данные прежней версии переносятся миграцией `0012_v0_1_0_schema`. Подробности — [release notes](docs/release-notes/v0.1.0.md), решения — ADR-0001…0006 в [docs/architecture](docs/architecture).

### Платформа сервера

- **Структура**: `core` (конфигурация, база, миграции, безопасность, ошибки, журнал), `models` (SQLAlchemy 2.1, `Mapped`), `schemas` (Pydantic 2), `services` (аналитика, светофор, доступ, журнал, импорт и экспорт, PDF, кэш), `api` (тонкие роутеры, зависимости прав), `cli` ([ADR-0001](docs/architecture/adr-0001-product-architecture.md)).
- **Стек**: FastAPI 0.162, SQLAlchemy 2.1, Alembic 1.20, Pydantic 2.14, psycopg 3, gunicorn 26 + uvicorn-worker, bcrypt 5, ReportLab 5, Matplotlib 3.11, openpyxl.
- **Ошибки API** — единый формат `{detail, code, fields}` по-русски; ошибки валидации полей — в `fields` для подсветки в формах; `X-Request-ID` у каждого ответа; заголовки безопасности.
- **Журнал сервера** текстом или JSON (`LOG_JSON`), без паролей, токенов и сессий.
- **Состояние**: `/api/health` сверяет схему базы с версией приложения (503 `degraded`, если не совпадает), `/api/version`, `/api/system/info` для администратора; OpenAPI — `/api/docs`.

### База данных и миграции

- **PostgreSQL 16** — основная СУБД (в `docker-compose.yml`); SQLite — для разработки (WAL, внешние ключи, юникодная `lower()` для поиска по кириллице) ([ADR-0002](docs/architecture/adr-0002-database-and-migrations.md)).
- Схемой управляет только Alembic: `create_all()` и ручное добавление столбцов при старте убраны. `python -m app.cli migrate` — миграции под advisory-блокировкой PostgreSQL, справочники, демо-данные (`DEMO_DATA`), первичный администратор.
- **`0012_v0_1_0_schema`** перестраивает все таблицы с переносом данных и устойчива к любому прежнему состоянию базы (Docker с историей Alembic, локальная без неё, пустая): префиксы `hr_`/`tp_`, общая `traffic_light_rules`, справочник `services`, `service_access`, `user_sessions`, `service_settings`, `data_imports`; год и неделя отчёта ТП — целые и уникальные, номер заявки Naumen уникален; единая конвенция имён ограничений, внешние ключи с каскадами, CHECK-ограничения, индексы под фильтры.
- **`0013_data_revisions`** — ревизии данных служб для согласованного сброса кэша ответов.
- `backend/scripts/sqlite_to_postgres.py` — перенос базы SQLite в PostgreSQL.

### Безопасность и доступ

- **Серверные сессии** в базе: httpOnly-cookie + CSRF-токен в заголовке; срок и простой сессии; список сессий в профиле и завершение любой; отзыв при смене пароля, сбросе и отключении пользователя ([ADR-0003](docs/architecture/adr-0003-sessions-and-csrf.md)).
- Ограничение частоты неудачных входов, выравнивание времени ответа, политика паролей, обязательная смена временного пароля; `SECRET_KEY` обязателен в production; защита последнего администратора.
- **Модель доступа**: роли «Администратор» и «Пользователь»; уровни доступа к службе «Просмотр», «Ввод данных», «Управление»; «только свои подразделения» для реестра службы персонала. Проверка прав на каждом эндпоинте — раньше чтение данных службы персонала, PDF и правила светофора партнёрств были доступны любому вошедшему ([ADR-0004](docs/architecture/adr-0004-access-model.md)).

### Интерфейс

- **Стек**: Vue 3.5, Vite 8, Pinia 4, Vue Router 5, ECharts 6 (только нужные модули: 579 КБ вместо 1037), Inter Variable в составе приложения; Chart.js и внешние шрифты удалены; `package-lock.json` пересобран (прежний был повреждён и ломал сборку).
- **Дизайн-система** на токенах: светлая и тёмная тема («как в системе» по умолчанию), палитра светофора, бренда и графиков из настроек; единые компоненты — заголовок страницы, карточка показателя со светофором, изменением и целью, карточка графика, панель фильтров, модальные окна, подтверждения, уведомления, пустые состояния, загрузка файлов ([ADR-0005](docs/architecture/adr-0005-design-system.md)).
- **Оболочка**: меню по службам с уровнем доступа, хлебные крошки, «?» — раздел руководства для текущей страницы, «Что нового», сворачиваемое меню, мобильная раскладка.
- **«Обзор»** — новая стартовая страница: главные показатели каждой доступной службы, светофор, свежесть данных, последние загрузки.
- Фильтры страниц сохраняются в адресной строке; личная настройка состава и порядка блоков дашбордов (хранится на сервере).
- **Встроенная справка**: руководства пользователя и администратора с оглавлением и поиском, PDF к текущей версии; история версий; «О программе».
- Профиль: личные данные, фото, смена пароля с индикатором надёжности, уровни доступа, активные сессии.

### Службы

- **Персонал**: дашборд одним запросом (динамика к прошлому месяцу, цели, воронка найма, светофор по месяцам, разрез по подразделениям); реестр приёмов и увольнений с фильтрами, причиной увольнения и выгрузкой в Excel; ввод данных месяца с сохранением только изменённого; сводка по месяцам, кварталам, полугодиям и годам; цели; пользовательские дашборды.
- **Техподдержка**: дашборд недельного отчёта на ECharts; недельный отчёт с проверкой уникальности недели; загрузка xlsx/csv в режимах «Дополнить» и «Заменить», выгрузка в формате исходного отчёта; сравнение периодов; заявки Naumen — загрузка с сопоставлением по номеру, аналитика; сопоставление отчёта и Naumen.
- **Партнёрства**: светофор каждой записи (худший из статуса, NDA, соглашения и срока сертификата); реестр с фильтром по светофору; аналитика; сводка по годам; хронология; правила светофора; выгрузка в Excel.
- **Светофор** персонала и техподдержки — общая страница настройки с проверкой порогов.
- **Журнал загрузок** файлов (кто, когда, сколько добавлено и обновлено) — в обзоре и на страницах служб.

### Администрирование

- Пользователи: поиск и фильтры, карточка с профилем и матрицей доступа к службам, временный пароль, отключение с завершением сессий; подразделения.
- Журнал изменений: фильтры, постраничный вывод, значения «до» и «после», выгрузка CSV.
- Палитры: предпросмотр, встроенные палитры, своя палитра; «О системе»: версия, схема базы, объёмы данных.

### PDF-отчёты

- Единый оформитель отчётов: шапка, фильтры, плитки показателей, таблицы со светофором, графики в цветах палитры.
- Шрифт DejaVu из состава matplotlib — в slim-образе Docker кириллица в PDF раньше ломалась.
- Новые отчёты техподдержки (недельный отчёт, заявки Naumen): раньше кнопка PDF на страницах ТП обращалась к несуществующим отчётам.

### Производительность

- Кэш готовых ответов аналитики в памяти процессов с ключом по ревизии данных службы: изменение данных в одном процессе сразу видно во всех; учитывает ограничение «свои подразделения».
- Пул соединений PostgreSQL, gunicorn с перезапуском процессов, сжатие ответов.
- Нагрузочный сценарий Locust (`loadtest/`) и проверка на 500 и 1000 одновременных пользователей — [отчёт](docs/performance/load-test-0.1.0.md), [ADR-0006](docs/architecture/adr-0006-performance.md).

### Исправлено

- Гонка при ленивом создании настроек ТП (500 на дашборде ТП при одновременных запросах).
- Поиск по кириллице без учёта регистра в SQLite.
- `NaN` в наборах данных Naumen.
- Пустой только что добавленный месяц больше не обнуляет карточки дашборда.

### Сборка, CI, тесты

- Docker: многостадийный образ, непривилегированный пользователь, проверка здоровья без curl, миграции перед стартом; compose с PostgreSQL и проверкой готовности.
- GitHub Actions: сервер (ruff, pytest с PostgreSQL 16, миграции с нуля), интерфейс (ESLint, Vitest, сборка), e2e (Playwright на демо-данных).
- Сервер: pytest — вход и сессии, матрица доступа, службы, импорт и экспорт, PDF, журнал, кэш, миграции на SQLite и PostgreSQL (совпадение схемы с моделями, обновление баз прежних версий). Интерфейс: Vitest для утилит и предметной логики, Playwright — сквозные сценарии.
