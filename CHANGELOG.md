# CHANGELOG

## v0.2.0 — 2026-11-01

Структура компании, модель доступа 2.0 и вход по учётной записи домена. Подразделения стали деревом с руководителями и подчинением; доступ складывается из профиля доступа для уровня сотрудника и личных настроек поверх него (область структуры, классы данных, глубина детализации, исходные записи, выгрузка); сотрудники входят с логином и паролем домена, структура и сотрудники загружаются из файлов и синхронизируются с Active Directory. Доступ существующих пользователей миграцией `0014_org_access` не меняется. Подробности — [release notes](docs/release-notes/v0.2.0.md), решения — ADR-0007…0009 в [docs/architecture](docs/architecture), проект сквозных отчётов 0.3.0 — [ADR-0010](docs/architecture/adr-0010-cross-reports.md).

### Структура компании

- **Данные** ([ADR-0007](docs/architecture/adr-0007-org-structure.md)): дерево подразделений (тип уровня, порядок, код, внешний идентификатор, источник), руководители с основным, у пользователя — основное подразделение, явный руководитель и «первое лицо»; имена уникальны среди соседних частичными уникальными индексами (без гонки параллельных запросов); типы уровней, предел вложенности и вид оргсхемы — в `app_settings`.
- **Правила подчинения**: «первое лицо» → явный руководитель → основной руководитель подразделения с подъёмом по дереву; проверки циклов, вложенности, имён и кодов с понятными сообщениями; признак основного руководителя не теряется; удаление подразделения — только без вложенных и с записью в журнал.
- **Снимок структуры** в памяти процесса по ревизии `org_revision`; `/api/org/tree` отдаёт все виды одним ответом, тело строится один раз на ревизию.
- **«Структура компании»** (`/org`): оргсхема, «Люди», дерево, таблица; общий поиск, «Уровней», «Развернуть / Свернуть», «Где я», масштаб, «Вписать» и перетаскивание; выбранное и вид — в адресе; боковая панель подразделения и сотрудника, у ведущих структуру — подчинение, должность и история.
- **«Подразделения»**: дерево с численностью и руководителями, добавление вложенного, изменение и перенос, руководители, удаление, «Типы уровней и вложенность».
- **«Импорт и экспорт»**: структура (JSON `dashboards.org-structure` v1), сотрудники (Excel, CSV, JSON; разбор различий «Система / Файл / Объединить / Своё», вопрос «тот же человек?»), быстрая загрузка списком, Active Directory — проверка → план → применение одной транзакцией; ничего не удаляется, руководители только добавляются.

### Доступ и пользователи

- **Модель доступа 2.0** ([ADR-0009](docs/architecture/adr-0009-access-model.md)): профиль доступа + личные настройки + уровни служб (в том числе «нет доступа»); область структуры (вся компания · своя ветка · своё подразделение, своя у службы), дополнительные подразделения, классы данных (операционные · персональные · финансовые), глубина детализации, исходные записи, выгрузка; действующий доступ с источником каждого значения.
- **Встроенные профили**: «Высшее руководство», «Руководитель направления», «Руководитель подразделения», «Специалист», «Сотрудник»; «Профили доступа» — карточки, редактор, сравнение; удаление используемого профиля — 409 с числом пользователей.
- **Проверки на сервере**: реестры и карточки — право на исходные записи; ФИО и причины увольнения — класс «персональные»; все выгрузки Excel/CSV/PDF — право на выгрузку; светофор записей партнёрств считает сервер, поэтому дашборд работает без доступа к записям; ключи кэша ответов учитывают область, классы данных и записи.
- **Полномочия** `org.manage` и `users.manage` — часть администрирования без роли администратора; администраторов изменяет только администратор.
- **«Пользователи»**: сводка и фильтры в адресе (роль, статус «без доступа», подразделение, профиль, способ входа), создание с паролем, входом по домену или без доступа, «Выдать доступ», сброс пароля («Перевести на пароль системы» для домена), удаление с предложением отключить; карточка с вкладками «Профиль», «Доступ», «Полномочия», «Журнал».
- **Интерфейс по правам**: недоступные разделы и кнопки скрыты, «Нет доступа» объясняет причину, профиль — «Мой доступ» простыми словами, в меню под именем — профиль доступа.

### Вход по домену и Active Directory

- **LDAP** ([ADR-0008](docs/architecture/adr-0008-users-ldap.md), ldap3): служебная привязка, поиск с экранированием логина, привязка от имени найденной записи, отключённые в AD не входят, LDAPS и StartTLS с проверкой сертификата; сопоставление по идентификатору каталога, идентификатору синхронизации AD и e-mail; создание при первом входе с профилем по группам каталога; 503 «Сервер домена не отвечает» для доменных учётных записей; пароль доменной учётной записи в системе не хранится.
- **«Вход по домену»**: состояние подключения, шифрование, создание учётных записей, профили по группам, замечания настройки, проверка подключения и поиск учётной записи без пароля сотрудника.
- **Синхронизация с AD** (`AD_SYNC_*`): постраничное чтение, путь подразделения из атрибутов или OU, руководитель из `manager`, руководители подразделений по подчинённым; отключаются только пришедшие из AD, включение не выполняется никогда. CLI для планировщика: `python -m app.cli org-sync (--ad | --csv ФАЙЛ) [--apply] [--create-missing] [--deactivate-missing] [--actor] [--json]`, коды выхода 0/1/2.
- Страница входа: подсказка домена, сообщения «сервер домена не отвечает» и «учётной записи нет».

### Службы и отчёты

- **Незаполненный показатель со светофором** — «Нет данных» (серый), а не «Критично»; сам пропуск — критичное нарушение полноты данных: предупреждение с «Заполнить» и метка «Не заполнено» на дашборде персонала, строка на «Обзоре» (в том числе для последней недели техподдержки), выделение на вводе данных, строка в PDF; в API — `missing` у метрики и списки у месяца и в «Обзоре».
- **PDF по фильтрам страницы**: сводка персонала — за выбранный диапазон периодов (`from_key`, `to_key`), недельный отчёт — по нескольким годам (`years`), сводка партнёрств — с фильтрами дашборда в подзаголовке; числа вправо, легенды не перекрывают столбцы, светофор в цветах светофора, знак «−».
- **`TIMEZONE`** (по умолчанию `Europe/Moscow`): границы дней в журнале изменений и время в PDF — по местному времени; `tzdata` в зависимостях.
- «Обзор»: период техподдержки — «31-я неделя 2026»; кэш «Обзора» и аналитики партнёрств учитывает дату.

### Исправлено

- Цель года оценивалась по последнему значению любого года (цель на 2099 показывалась достигнутой) — теперь по данным своего года.
- Фильтр года заявок Naumen растягивал помесячные графики до года решения (21 месяц вместо 12) — ось по месяцам регистрации.
- Сравнение периодов техподдержки сравнивало интервалы разной длины (+124,9 %) — только равные интервалы.
- Неудачный запрос выглядел как «нет данных» — теперь «Не удалось загрузить» с «Повторить», без мигания пустого состояния.
- Диалоги: Esc закрывает только верхнее окно, фокус удерживается внутри и возвращается, доступное имя окна, без прокрутки страницы под окном, на телефоне окно не шире экрана.
- Несохранённые пороги светофора терялись при переходе между службами; линии целей и порогов выходили за ось; ошибки поля 409 дублировались уведомлением; строки реестров не открывались с клавиатуры.
- Раскладка на телефоне и планшете: настройка светофора, выбор месяца, сессии в профиле, журнал, недельный отчёт — без горизонтальной прокрутки на ширинах 390–1920.
- CSV недельного отчёта: целые числа без «,0».

### База данных и миграции

## v0.1.0 — 2026-11-01

Первая версия продукта «Дашборды компании». Прототип переработан целиком: сервер на зрелой платформе с PostgreSQL и миграциями, серверные сессии и единая модель доступа к службам, новый интерфейс на собственной дизайн-системе, стартовая страница «Обзор», встроенные руководства и история версий, тесты, CI и документация. Все данные прежней версии переносятся миграцией `0012_v0_1_0_schema`. Подробности — [release notes](docs/release-notes/v0.1.0.md), решения — ADR-0001…0006 в [docs/architecture](docs/architecture).

### Платформа сервера

- **Структура**: `core` (конфигурация, база, миграции, безопасность, ошибки, журнал), `models` (SQLAlchemy 2.1, `Mapped`), `schemas` (Pydantic 2), `services` (аналитика, светофор, доступ, журнал, импорт и экспорт, PDF, кэш), `api` (тонкие роутеры, зависимости прав), `cli` ([ADR-0001](docs/architecture/adr-0001-product-architecture.md)).
- **Стек**: FastAPI 0.162, SQLAlchemy 2.1, Alembic 1.20, Pydantic 2.14, psycopg 3, gunicorn 26 + uvicorn-worker, bcrypt 5, ReportLab 5, Matplotlib 3.11, openpyxl.
- **Ошибки API** — единый формат `{detail, code, fields}` по-русски; ошибки валидации полей — в `fields` для подсветки в формах; `X-Request-ID` у каждого ответа; заголовки безопасности.
- **Журнал сервера** текстом или JSON (`LOG_JSON`), без паролей, токенов и сессий.
- **Состояние**: `/api/health` сверяет схему базы с версией приложения (503 `degraded`, если не совпадает), `/api/version`, `/api/system/info` для администратора; OpenAPI — `/api/docs`.

### База данных и миграции

- **PostgreSQL 16** — основная СУБД (в `docker-compose.yml`); SQLite — для разработки (WAL, внешние ключи, юникодная `lower()` для поиска по кириллице) ([ADR-0002](docs/architecture/adr-0002-database-and-migrations.md)).
- Схемой управляет только Alembic: `create_all()` и ручное добавление столбцов при старте убраны. `python -m app.cli migrate` — миграции под advisory-блокировкой PostgreSQL, справочники, демо-данные (`DEMO_DATA`), первичный администратор.
- **`0012_v0_1_0_schema`** перестраивает все таблицы с переносом данных и устойчива к любому прежнему состоянию базы (Docker с историей Alembic, локальная без неё, пустая): префиксы `hr_`/`tp_`, общая `traffic_light_rules`, справочник `services`, `service_access`, `user_sessions`, `service_settings`, `data_imports`; год и неделя отчёта ТП — целые и уникальные, номер заявки Naumen уникален; единая конвенция имён ограничений, внешние ключи с каскадами, CHECK-ограничения, индексы под фильтры.
- **`0013_data_revisions`** — ревизии данных служб для согласованного сброса кэша ответов.
- `backend/scripts/sqlite_to_postgres.py` — перенос базы SQLite в PostgreSQL.

### Безопасность и доступ

- **Серверные сессии** в базе: httpOnly-cookie + CSRF-токен в заголовке; срок и простой сессии; список сессий в профиле и завершение любой; отзыв при смене пароля, сбросе и отключении пользователя ([ADR-0003](docs/architecture/adr-0003-sessions-and-csrf.md)).
- Ограничение частоты неудачных входов, выравнивание времени ответа, политика паролей, обязательная смена временного пароля; `SECRET_KEY` обязателен в production; защита последнего администратора.
- **Модель доступа**: роли «Администратор» и «Пользователь»; уровни доступа к службе «Просмотр», «Ввод данных», «Управление»; «только свои подразделения» для реестра службы персонала. Проверка прав на каждом эндпоинте — раньше чтение данных службы персонала, PDF и правила светофора партнёрств были доступны любому вошедшему ([ADR-0004](docs/architecture/adr-0004-access-model.md)).

### Интерфейс

- **Стек**: Vue 3.5, Vite 8, Pinia 4, Vue Router 5, ECharts 6 (только нужные модули: 579 КБ вместо 1037), Inter Variable в составе приложения; Chart.js и внешние шрифты удалены; `package-lock.json` пересобран (прежний был повреждён и ломал сборку).
- **Дизайн-система** на токенах: светлая и тёмная тема («как в системе» по умолчанию), палитра светофора, бренда и графиков из настроек; единые компоненты — заголовок страницы, карточка показателя со светофором, изменением и целью, карточка графика, панель фильтров, модальные окна, подтверждения, уведомления, пустые состояния, загрузка файлов ([ADR-0005](docs/architecture/adr-0005-design-system.md)).
- **Оболочка**: меню по службам с уровнем доступа, хлебные крошки, «?» — раздел руководства для текущей страницы, «Что нового», сворачиваемое меню, мобильная раскладка.
- **«Обзор»** — новая стартовая страница: главные показатели каждой доступной службы, светофор, свежесть данных, последние загрузки.
- Фильтры страниц сохраняются в адресной строке; личная настройка состава и порядка блоков дашбордов (хранится на сервере).
- **Встроенная справка**: руководства пользователя и администратора с оглавлением и поиском, PDF к текущей версии; история версий; «О программе».
- Профиль: личные данные, фото, смена пароля с индикатором надёжности, уровни доступа, активные сессии.

### Службы

- **Персонал**: дашборд одним запросом (динамика к прошлому месяцу, цели, воронка найма, светофор по месяцам, разрез по подразделениям); реестр приёмов и увольнений с фильтрами, причиной увольнения и выгрузкой в Excel; ввод данных месяца с сохранением только изменённого; сводка по месяцам, кварталам, полугодиям и годам; цели; пользовательские дашборды.
- **Техподдержка**: дашборд недельного отчёта на ECharts; недельный отчёт с проверкой уникальности недели; загрузка xlsx/csv в режимах «Дополнить» и «Заменить», выгрузка в формате исходного отчёта; сравнение периодов; заявки Naumen — загрузка с сопоставлением по номеру, аналитика; сопоставление отчёта и Naumen.
- **Партнёрства**: светофор каждой записи (худший из статуса, NDA, соглашения и срока сертификата); реестр с фильтром по светофору; аналитика; сводка по годам; хронология; правила светофора; выгрузка в Excel.
- **Светофор** персонала и техподдержки — общая страница настройки с проверкой порогов.
- **Журнал загрузок** файлов (кто, когда, сколько добавлено и обновлено) — в обзоре и на страницах служб.

### Администрирование

- Пользователи: поиск и фильтры, карточка с профилем и матрицей доступа к службам, временный пароль, отключение с завершением сессий; подразделения.
- Журнал изменений: фильтры, постраничный вывод, значения «до» и «после», выгрузка CSV.
- Палитры: предпросмотр, встроенные палитры, своя палитра; «О системе»: версия, схема базы, объёмы данных.

### PDF-отчёты

- Единый оформитель отчётов: шапка, фильтры, плитки показателей, таблицы со светофором, графики в цветах палитры.
- Шрифт DejaVu из состава matplotlib — в slim-образе Docker кириллица в PDF раньше ломалась.
- Новые отчёты техподдержки (недельный отчёт, заявки Naumen): раньше кнопка PDF на страницах ТП обращалась к несуществующим отчётам.

### Производительность

- Кэш готовых ответов аналитики в памяти процессов с ключом по ревизии данных службы: изменение данных в одном процессе сразу видно во всех; учитывает ограничение «свои подразделения».
- **Очередь запросов к базе**: сессию получают не больше запросов, чем соединений в пуле процесса (`DB_CONCURRENCY`), остальные ждут без потока и соединения; дольше `DB_QUEUE_TIMEOUT` — ответ 503 «Сервер перегружен» с `Retry-After`. Исправляет взаимную блокировку пула потоков и пула соединений, из-за которой при 1000 пользователях запросы зависали на 30–60 с.
- Проверка сессии, CSRF и прав — одна транзакция; вход возвращает соединение до проверки пароля; PDF-отчёты строятся не больше `PDF_CONCURRENCY` одновременно в асинхронной очереди.
- Пул соединений PostgreSQL 5 + 4 на процесс (9 процессов укладываются в `max_connections` = 100), gunicorn с перезапуском процессов, сжатие ответов (готовые ответы кэша хранятся сжатыми).
- Нагрузочный сценарий Locust (`loadtest/`). **1000 одновременных пользователей на 4 ядрах: p50 12 мс, p95 46 мс, без ошибок сервера**; 500 — p50 10 мс, p95 35 мс — [отчёт](docs/performance/load-test-0.1.0.md), [ADR-0006](docs/architecture/adr-0006-performance.md).

### Исправлено

- Гонка при ленивом создании настроек ТП (500 на дашборде ТП при одновременных запросах).
- Поиск по кириллице без учёта регистра в SQLite.
- `NaN` в наборах данных Naumen.
- Пустой только что добавленный месяц больше не обнуляет карточки дашборда.
- Имя скачиваемого файла: в части браузеров файл сохранялся под именем «download»; для старых клиентов имя латиницей.
- Ошибки полей формы показываются рядом с полями, без повторного всплывающего уведомления.
- Короткая палитра графиков заполняет все семь цветов; приглушённый цвет бренда применяется.

### Сборка, CI, тесты

- Docker: многостадийный образ, непривилегированный пользователь, проверка здоровья без curl, миграции перед стартом; compose с PostgreSQL и проверкой готовности.
- GitHub Actions: сервер (ruff, pytest с PostgreSQL 16, миграции с нуля), интерфейс (ESLint, Vitest, сборка), e2e (Playwright на демо-данных).
- Сервер: pytest — вход и сессии, матрица доступа, службы, импорт и экспорт, PDF, журнал, кэш, миграции на SQLite и PostgreSQL (совпадение схемы с моделями, обновление баз прежних версий). Интерфейс: Vitest для утилит и предметной логики, Playwright — сквозные сценарии.
